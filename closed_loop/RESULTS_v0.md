# 第8+9步 v0:最小流式闭环结果(2026-07-27)

设置:合成 lookup 40 题(seed 13,避开 pilot 的 7/11),Qwen3-8B 贪心,每 16 token 一块、块末额外前向读 layer 11 探针概率 p。探针为现训逻辑回归(pilot8b 20 条 synthetic 轨迹,标签=未来 32 token 内有 CALL),按轨迹 16/4 切分 held-out AUROC **0.957**。开火=向上下文追加 `[SYSTEM NOTE: prefetched lookup("<实体>") = <正确值>]`,v0 只赌时机不赌内容。代码 `loop_v0.py`,逐条记录 `results_v0.jsonl`,p 轨迹 `readings_v0.jsonl`,日志 `../logs/loop_v0.log`。

## 探针在流式读数下没有失灵

块末流式读数(521 个,正例率 13.1%)AUROC **0.857**。比离线逐 token 的 0.957 低,原因是流式只在 16-token 边界采样、且训练数据含 RESULT 后的续写段而流式读数全部在首次调用前;0.857 足以支撑阈值开火,不构成失灵。

## 五策略表(n=40)

| 策略 | acc | 平均 gen_tokens | 开火率 | 平均开火时刻 | 平均 lead | 免调用率 |
|---|---|---|---|---|---|---|
| baseline(不注入) | 0.875 | 227.9 | — | — | — | 0.10 |
| t=0 开火 | **1.000** | **9.2** | 1.00 | 0 | 208.0 | 1.00 |
| p>0.5 | 0.875 | 140.6 | 0.95 | 75.8 | 139.9 | 0.95 |

| p>0.99 | 0.900 | 224.3 | 0.80 | 191.5 | 27.4 | 0.85 |

补充切片:

- 阈值单调推迟开火:0.5→0.9→0.99 的平均开火时刻 75.8→129.8→191.5,lead 139.9→84.5→27.4,相对 baseline 的省 token 从 91.9(仅开火题)一路缩到 **4.5**——p>0.99 即便开了火,平均也只省 4.5 token,gen_tokens(224.3)与 baseline(227.9)已无可辨差异。
- 死区被直接量出:全部 97 次阈值开火里,lead 与省 token 的 Pearson 相关 **0.910**;lead≤32 的开火平均省 **-6.4** token(反而变慢),lead>32 的平均省 **+80.7**。p>0.99 的平均 lead 恰好落在 27.4,整段策略泡在死区里。
- 注入内容本身无害:t=0 开火 40/40 全对且全部免调用,9.2 token 直接出答案;各阈值策略 acc 0.875-0.900 与 baseline 持平,错题主要是 baseline 就不调用瞎猜的 4 题(qid 3/4/7/10)及个别注入后仍答错的题。收益差异全部来自时机,不来自内容。

## 结论

置信度阈值越高、开火越晚、离死区越近:p 从 0.5 提到 0.99,开火时刻从 75.8 推迟到 191.5,lead 从 139.9 缩到 27.4,省 token 从 87.3 塌到 3.6(仅开火题口径 91.9→4.5),而 lead≤32 的开火平均为负收益——"等探针确信"这条最自然的基线自己走进了死区,数字支持"时机必须学":要吃到 t=0 那档 96% 的 token 节省,开火决策必须在低置信区间主动提前,而不是等置信度自然爬过阈值。

# SPORK: Self-Speculative Forking to Accelerate Agentic LLM Inference

- arXiv 2607.03333（v1, 2026-07-03）· Bai/Zheng/Lu/Shu（清华）+ Lv（美团）· 开源 github.com/baihuajun24/spork

- 读于 2026-07-20

## TAMMIC

- **Motivation**: agent 想—调—等循环让 GPU 空转（本文实测占墙钟 16–37%，引 PASTE 报告 35–61%）；已有投机方案都要外挂预测器/历史轨迹/工作流图，没法 day-one 上线。
- **Method**: 让模型预测自己的下一次调用：主流出第一个 token 后共享 KV cache 分叉探针，强制它吐工具调用、提前执行。D1 前缀缓存分叉压探针成本（1.6s→0.35s）、D2 置信度门控挑时机、D3 被拒探针回收成投机解码草稿。
- **Insight**: 工具名起点即可知（74.6–99.6%）；参数要"想着想着才定"（7.6%→97.5% 随 CoT）；置信度 logprob 分得开对错（GAIA 0.90 vs 0.46）；被拒探针中位数 18 token 可回收（35–50% 调用体）。失效条件：关 thinking、工具 <2s、模型格式与强制前缀不合。
- **Contribution**: 免训练自投机分叉控制器，GAIA P95 −18%（131.9→108.1s）且精度 ±1pp。

## 关键机制

- **D1** 前缀缓存分叉：prefill 1.3s→0.05s；必须错峰派发（同时发有 2.5× prefill 争抢）。
- **D2** 门控信号 = 工具名 token 跨度上的**最小** top-1 概率（刻意保守）；GAIA 997 探针上扫 F1 最大点：precision 88%、recall 100%、滤掉 77% 探针。否决了固定延迟/全词表熵/学习型分类器三个替代。
- **D3** 严格接受判据 = 名＋序列化参数逐字全等；**刻意不做 name-only 门槛**（同名不同参在副作用工具上危险）。被拒探针当 ngram 投机解码草稿，每被拒轮省 ~0.6s。
- 接受率按"轮"vs 按"探针"两套口径差数倍（101 轮 vs 2124 探针），读表要分清。

## FOCUS 答案（读前问题）

1. **分叉开销**：无 D1 探针 1.6s → D1 后 0.35s；主流 TPOT +0.22%；开销全计入 EQ1 每轮开销项，被 D2（滤 77%）/D3（回收 0.6s/被拒轮）消化。
2. **只预测工具名？** 否，预测的是完整调用（名＋参数），接受判据逐字全等。但名 74.6–99.6% vs 参数起点 7.6%，参数难猜正是 D2/D3 的设计动机。
3. **门控阈值**：min-prob 信号；GAIA 单基准上选 F1 最大工作点；跨负载是否要重标定未明说；no-think 模式下信号饱和（对错都 ≈0.979）失效。

## 局限（作者自认 + 读者）

- 只投机只读工具；写操作需沙箱/检查点回滚（未来工作）。
- 闭源 API 装不上（要 completions 强制前缀 + per-token logprob）。
- 需空闲算力；重批量部署收益缩水。
- 读者：只测 Qwen 系列，跨模型家族泛化存疑（附录 F 格式失效案例）；每轮只投机一个调用，不递归猜 N+2 步。

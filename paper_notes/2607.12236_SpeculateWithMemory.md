## TAMMIC

- **Motivation**: 现有 agent 投机执行全是无状态的：处理过 500 次客服对话的投机器和一次没见过的表现一样。
- **Method**: 给投机器（外部小模型）外挂三套在线记忆：对比转移表（动作接龙统计、分记成败）、情景记忆（向量检索相似片段＋miss 案例）、混淆追踪器（同种错误 ≥3 次写进提示硬性禁止）。全部规则更新、零推理延迟（仅 <50ms embedding 查询）。
- **Insight**: 动作预测相对 +19–39%；观察预测在 ALFWorld 16.3%→40.0%（2.5×）；估算延迟节省随经验 ∼28%→50%+；换投机器模型 delta 一致（model-agnostic）。但组件全开不总最优（VWA 最优是 Episodic）。
- **Contribution**: 第一个"记忆帮 speculator 而非 actor"的工作，命中率随经验爬升、加速完全无损。

## 三型投机框架（§2.1）

- Type 1 猜动作（省环境等待）· Type 2 猜观察（省 LLM 调用）· Type 3 连环猜（都省）。
- 安全红线：动作类型＋全部参数**精确匹配**才用；只读白名单（从 API schema 导出）才预启动。
- lossless 依据 = "只允许可丢弃的操作被投机"这条前置约束，**没有回滚机制**。

## 三套记忆更新规则（§2.2）

- 转移表：相邻动作对累加成功/失败计数＋参数名集合；输出 Confidence（转移占比）、SuccessRate。
- 情景记忆：(context, actions, observation, arg_sources, outcome, lesson) 元组，规则模板生成；arg_sources 靠对先前观察做子串匹配；text-embedding-3-small 余弦 top-k；专记 speculation-miss 案例。
- 混淆追踪器：(预测类型, 实际类型) 计数 ≥3 → 提示词硬约束。每任务完成后在线更新。

## FOCUS 答案（读前问题）

1. **观察预测粒度**：完整观察内容的精确匹配（"observation exact match"），不是摘要/分类。做在反馈模板化的 ALFWorld（134 集、13 动词）和 PDDL（60 任务）；τ²/HotpotQA 连环猜但主指标只算动作。
2. **重复曲线**：有两张：Fig 1 右（x=episodes 0–120，y=估算延迟节省）和 Fig 3（x=任务序号，y=累积准确率，六个基准各一幅）。**注意 y 是估算/准确率，墙钟实测在 Fig 4**。Type 2 爬坡、Type 1 只平移 3–5pp（收益来自内容而非积累）。
3. **更新规则**：见上节。
4. **lossless**：空闲窗口投机＋只读白名单＋全量精确匹配＋miss 即丢弃，actor 上下文逐字相同。

## 局限（作者 + 读者）

- 组件全开不总优，缺按域自动选择（future: confidence-based memory routing）。
- 网页 UI 索引本质不可预测，卡住绝对准确率。
- 读者：回放评测可能过拟合录像；无遗忘机制应对分布漂移；"5% 净赚"未计下游负载；参数级错误的纠错覆盖未明说。

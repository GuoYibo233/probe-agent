# 第3步先导:轨迹+隐藏态采集试跑(2026-07-27)

**产出**:`data/pilot/` 50 条轨迹(合成 lookup 25 + HotpotQA 25),Qwen3.5-4B,合计 494MB(约 10MB/条)。

每条 .pt 含:全 token 流、prompt 长度、第 10/14 层(30%/45% 深度)逐 token 隐藏态 fp16、工具调用标签(token 位置+查询串+段号)、插入区间掩码(RESULT 段不算模型生成)、答案与判分、耗时。

**路线判定(第3步的最脆处,已裁决)**:HF transformers 慢跑 + 事后一次全序列前向抽隐藏态的路线成立——贪心解码下重算逐位等价,单条轨迹开销 10-60s,存储 10MB/条。千条规模 ≈ 10GB / 单卡一天,舰队半天。**不需要碰 vLLM 取隐藏态**。

**头③参数头的第一个可测数字**:calls 标签里带完整查询串,配合 token 流可直接量"参数是上下文子串/记忆候选"的覆盖率(第 6 步讨论时定的理论上限指标),数据已就位。

坑:采集时的 4B 复读脱轨轨迹(见 hotpot_inject/FINDINGS.md)混在 50 条里,训练前按 em/soft 与 gen_tokens 过滤;下一轮采集换 8B 或加 degen 截断(collect_v0 尚未带 hotpot_v1 的 degen 防护,放量前要移植)。

## 第5步 v0 结果(2026-07-27,train_probe_v0.py)

头①(未来 32 token 内会否发调用)线性探针,50 条 pilot 轨迹按轨迹切 40/10:
- **layer 10(31% 深度):AUROC 0.981**;layer 14(44%):0.972;位置分数基线 0.371。
- 逐 token 思考中段读数,信号比 When2Tool 的生成前单次读数(0.89-0.96)更强——第 5 步"中段信号弱"的担忧排除。
- 边界:单模型(Qwen3.5-4B)、混合任务 50 条、正例率 4.3%、含 4B 复读轨迹未过滤。放量后按任务/模型分开验证。

## 第4步 v0 结果(2026-07-27,labeler_v0.py)

50 条 pilot 轨迹(soft=true 的 30 条)× 每条 ~7 个注入位置 = 191 条 benefit(t) 标签,4 卡半小时。
- **benefit 形状正确**:thinking 开场注入 +129 token,贴近调用点(lead≤25)缩到 9~27——死区形状在回放标签里重现,时机头有得学。
- **已知缺陷**:ans_match 用严格字符串比对 baseline 答案,措辞变化全判 false(0.08-0.33 失真)。放量前换 hotpot_v1.grade() 软匹配 + 合成题直接解析 gold 数值。
- 管线本身(存储轨迹→按位置回放→注入→续跑→打标)端到端跑通,status ok 率 90%。

## 第5步 v1(8B,跨任务)

train_probe_v1.py,60 条 Qwen3-8B 轨迹(synthetic/hotpot/2wiki 各 20),层 11/16,H=32:

| 评估 | 切分 | layer11 AUROC | layer16 AUROC | 位置基线 |
|---|---|---|---|---|
| 混合(按轨迹 80/20) | 48/12 | 0.899 | 0.901 | 0.656 |
| synthetic+2wiki → hotpot | 40/20 | 0.862 | 0.897 | 0.677 |
| synthetic → 2wiki | 20/20 | 0.660 | 0.636 | 0.568 |

头①信号在 8B 上依然成立且能跨到未见任务:混合与跨到 hotpot 都在 0.86-0.90,远高于位置基线,说明探针学到的是任务无关的"要调用了"的表征而不是位置规律。只用合成任务训则泛化崩到 0.64-0.66,放量采集必须覆盖真实多跳任务,不能靠合成数据单撑。

## 第6步 v0(参数头,8B)(2026-07-27,train_param_head_v0.py)

60 条 pilot8b 轨迹、80 个 call,锚点取调用前第 25 个生成 token,bilinear 打分(双侧线性投影到 256 维),5 个切分种子。
- **打分器本身成立**:凡是真参数已出现在锚点上下文里的样本(每 call 1 正例 + ≤32 负例),held-out top-1 汇总 19/22 = **0.864**,top-5 五个种子全部 **1.000**——第 11 层隐藏态足以从候选池里挑出参数。
- **真正的瓶颈在候选可得性,不在打分**:query 在完整调用前文本里 100% 是原文子串(印证第3步结论),但截到"调用前 25 token"后只剩 **33.8%**——查询串多数是模型在临调用前最后 25 token 内才拼写出来的,launch 抽取器自身覆盖 27.5%。参数头要在 25 token 提前量下可用,下一步必须换目标:不是匹配模型将要写的完整 query 字面串,而是预测其组成成分(实体+关系词各自都在上下文里),或者缩短提前量换覆盖率。
- 边界:可用样本仅 27 个(覆盖率过滤后),单模型单批数据,数字只定性成立。

## 第7步 v0(时机头,8B)(2026-07-27,train_timing_head_v0.py)

243 条 ok 标签(37 条轨迹),目标 y = benefit/baseline_gen,输入第 11 层注入点隐藏态,两层 MLP(256),按轨迹 80/20 切,5 个切分种子:

| 模型 | held-out Spearman(mean [min,max]) | MSE |
|---|---|---|
| MLP(隐藏态) | **0.454** [0.337, 0.576] | 0.692 |
| 线性(lead/baseline_gen,oracle) | 0.545 [0.424, 0.661] | 0.510 |
| 全局均值 | - | 0.596 |

lead 桶(种子 0 测试集,n=48,预测均值 vs 真值均值):

| lead 桶 | n | 预测 | 真值 |
|---|---|---|---|
| >100 | 11 | 0.563 | 0.668 |
| 51-100 | 10 | 0.197 | 0.078 |
| 26-50 | 7 | -0.065 | -0.457 |
| 11-25 | 7 | 0.130 | -0.180 |
| 1-10 | 6 | 0.111 | 0.110 |
| 0 | 7 | -0.182 | -0.478 |

- 时机头从隐藏态学到了"贴近调用点收益骤降"的整体形状:>100 桶预测 0.563、lead=0 桶预测 -0.182,方向与真值一致且 Spearman 0.454 明显优于全局均值——关键在于它推理时不需要知道距调用点还有多远,而 lead 基线需要这个不可得的 oracle 量。
- 但它尚未超过 oracle lead 线性基线(0.545),说明当前隐藏态读出的主要还是位置类信息、没有拿到超出 lead 的内容增量;换 weight decay(1e-4~1e-1)与训练轮数(150/300)结论不变(0.448-0.468),243 样本、37 条轨迹下种子间波动 0.337-0.576,数字只定性成立,超越 oracle 基线与否要等放量后再判。

## Verdict

The tree and the settings idea are sound, but three things in the plan do not survive contact with the code: `train/train.py` merges two trainers that share almost nothing except the optimizer loop and lands at roughly 1,500 lines, the inject stage needs two trained probes plus eval's temperature rather than one training run, and the identity rule skips a downstream stage whenever the upstream directory grew, because tasks and seeds are outside the key and downstream keys carry only the upstream key. A second group of problems is missing code rather than wrong code: continue-from-checkpoint does not exist today, the AppWorld environment leaks nine things past the five methods, the two cut rules are different on purpose, and the loop's concurrency (task claiming across twelve pieces) has no home. The plan is implementable in about the stated number of files if train and eval each split in two, and if the settings loader is written as a 300-to-400-line module rather than a short helper.

## Findings

**1. `train/train.py` is two trainers, not one, and will be about 1,500 lines.**
Plan: one trainer with method and tuning as settings values (§`train/train.py`, lines 491-507). Code: ctool batches whole events through a `DataLoader` and a `collate` that finds boundary token positions (`pipeline/train/train_causal_tool.py:165-186`), applies a linear head on those positions (`:191-208`), scores accuracy at boundaries (`:308-321`) and saves backbone plus `head.pt` plus `label_map.json` (`:516-536`). cgen/cparam pack rows of one event into one sequence with a custom additive mask and position ids (`pipeline/train/share_data.py:362-479`), batch by a token budget (`:499-532`), run the backbone and `lm_head` on loss positions only (`train_causal_share.py:140-176`), evaluate by validation CE plus greedy exact match (`:243-293`, `train_causal_callgen.py:339-362`) and save a full `AutoModelForCausalLM` (`train_causal_share.py:1257-1263`). Defaults conflict: `--accum 4`/`--epochs 3`/`--align-tol 3e-4` (`train_causal_tool.py:337-345, 91`) against `--accum 2`/`--epochs 1`/`--align-tol 2e-5` (`train_causal_share.py:950-954, 989`). Line counts of what folds in: 543 + 1293 + 611 + 156 + about 150 lines of constants and `build`/`eval_gen` from the row-wise files. After removing the alignment code (to the test), read-only branches, the mbert version gate, and duplicated argparse/logging, about 1,500 lines remain, two of them being the training loops themselves. Consequence: the file breaks principle 6 and the 800-line mark by a factor of two. Change: `train/train_ctool.py` (classification head, about 450 lines), `train/train_gen.py` (packed causal LM for cgen and cparam, about 550), `train/packing.py` (today's `share_data.py` without the row-wise imports, about 450). cgen versus cparam is one axis inside `train_gen.py`; ctool is not.

**2. "Continue from the last checkpoint" is new code, not a merge, and mid-epoch continuation is not reproducible for ctool.**
Plan: a partial train directory is continued from `last/` (lines 297-298, 500-501). Code: both trainers refuse a directory that already holds `train_log.jsonl` (`train_causal_share.py:1017-1020`, `train_causal_tool.py:380-383`); only `best/` is ever written (`train_causal_share.py:1257-1282`, `train_causal_tool.py:516-536`); no optimizer, scheduler, RNG or step state is saved anywhere (grep of `torch.save|save_pretrained|last/` finds only the `best/` writes). The packed trainer's data order is a pure function of `seed + ep` (`share_data.py:482-496`), so skipping `u` finished updates would reproduce it; ctool uses `DataLoader(shuffle=True)` with no generator (`train_causal_tool.py:440-443`), so it cannot. Cost of `last/` for a full 4B run in fp32 with AdamW: weights plus two moment tensors, about 48 GB per checkpoint on NFS. Change: continue at epoch boundaries only (save `last/` after each epoch's eval, including optimizer state and the epoch counter), and make ctool's shuffle seeded; or state that a partial train directory is deleted and restarted.

**3. The key leaves tasks and seeds out, but downstream keys carry only the upstream key, so growth upstream is invisible downstream.**
Plan: sample and inject extend in place and tasks/seeds are outside the key (lines 293-297); build's key is its section plus the sample key (286-289); a directory marked done is skipped. Code: the builder globs the whole trajectory directory each run (`pipeline/annotate/build.py:61-64, 172-187`) and starts over. Consequence: sample 100 tasks, build, train; then sample 200 tasks into the same directory; build's key is unchanged, `meta.json` says done, build is skipped, train is skipped, and the ledger says the 200-task run produced the old probe. Change: the sample and inject stages write a manifest of completed (task, seed) pairs; build's key includes a hash of that manifest; train's key then changes through build's key. Also note the builder's directory conventions die with the new layout: model lookup by directory suffix (`build.py:64, 257`; `pipeline/annotate/rules.py:23`), the glob `appworld_*/appworld_*.jsonl` (`build.py:177, 243-245`), and the official split files that today live in `pipeline/configs/*.json` (`pipeline/configs/p1_gptoss.json:10-14`) need a row in `constants/path_datasets.yaml`.

**4. Inject needs two probes and eval's temperature; the plan names one training run and puts inject's upstream at train.**
Plan: `inject.probe: train_probe/ctool_on_qwen06`, upstream `train` (lines 268, 283). Code: the probe service loads a ctool run for `/score` and a cgen run for `/gen` (`pipeline/inject/probe_server.py:154-157, 231`) and reads the softmax temperature from the ctool run's `REPLAY_REPORT.json` (`:118-119`), which eval writes (`pipeline/eval/eval_tool.py:213-226` fits it). Consequence: as written, inject cannot start. Change: two settings, `inject.probe_score` and `inject.probe_gen`, each naming an eval run; inject's upstream is eval; the plan's `theta` stays manual (matches `probe_server.py:229-230`).

**5. The cut rule is two rules on purpose; one `cut_points.py` must pick one and bump a VERSION.**
Plan: one rule offline and live (lines 363-370). Code: offline cuts are sentence ends by `m.end()`, thinned to `MAX_BOUNDS=64` evenly spaced points (`pipeline/annotate/rules.py:26-47`); live cuts are by `m.start()` with no thinning, and the docstrings say why: under streaming the whitespace after a sentence end arrives in pieces, so an end-based cut is counted twice, and thinning changes as the text grows (`pipeline/inject/live_appworld.py:165-187`). Change: the shared enumerator is the live rule (start positions, `MIN_THINK//2` filter); build applies its own `build.max_cuts` cap after enumeration and records it in its key; the plan should say this changes every existing dataset. Separately, the probe input format `assemble`/`clip` with `HIST_ROUNDS`, `RESULT_CAP`, `MIN_THINK` (`rules.py:17-22, 50-62`) is used by build, the live loop (`live_appworld.py:483, 501`) and nothing in the plan names it; it belongs in `cut_points.py` (rename to `probe_input.py`) or its own `any` file.

**6. "Probe off = one chat request" is not today's baseline path, and the two loops write different records.**
Plan: `chat()` when the probe is off, `stream()` when on (lines 407-411, 464-466); one loop for sample and inject (451-457). Code: today's collection default is `api: harmony` (`configs/presets/default.json:18`): a hand-assembled harmony prompt sent as text to `/completions` with the client-pinned date (`envs/collect/common.py:104-129, 233-272`), because the chat parser drops segments (`common.py:47-50`). The live control arm is `--no-probe`, the same streamed-ids path minus the probe (`live_appworld.py:438, 457, 632-633`), and the identical-tokens result between the chat endpoint and `/render` holds only with the server date pinned (`envs/serve_logs/launch_vllm_splice.py:32, 60`; `pipeline/inject/ident3_gate.py`). The records differ: `usage.in/out`, `out_token_ids`, `prompt_token_ids` and `eval` as a string (`common.py:259-272`; `envs/collect/run_appworld.py:231`) against `usage.prompt_tok/gen_tok/req`, `gen_ids`, `prefix_sha`, `text_ids_consistent` and `eval` as a dict (`live_appworld.py:798-802, 829-831`); the scorer patches over both (`pipeline/inject/score_live.py:70-88`). Consequence: an inject run paired with a chat-sampled baseline compares two generation paths, and every existing sample run is in a third record format. Change: sample and the inject control both use `stream()` with the probe switch off; `chat()` exists only inside `serve_agent.py`'s render-equals-server check; `task_record.py` defines one gen record and the loop gets a VERSION from day one.

**7. AppWorld leaks past the five methods; the interface needs a per-run open, a call-execution step distinct from the code step, and cleanup.**

Code: the loop must `chdir` to the AppWorld home before importing it (`run_appworld.py:149-150`; `pipeline/inject/exec_calls.py:130-131`); the experiment name must differ per (task, seed) because AppWorld deletes the experiment directory on reopen (`run_appworld.py:85-94`); the live arm passes `random_seed=APPWORLD_SEED` (`live_appworld.py:760-761`; constant at `exec_calls.py:139-142`) while the sampler passes nothing (`run_appworld.py:186-187`), a seed difference between arms; per-task outputs are deleted after each task for quota reasons (`live_appworld.py:754-756`); rollback is `save_state(CKPT)`, `execute`, `load_state(CKPT)`, `_set_datetime()` and a time-freeze assertion (`live_appworld.py:305-321`; `exec_calls.py:564-569`); the predicted call is not executable as written and goes through `requote` with the `ALWAYS_STR` heuristic and the shell namespace (`exec_calls.py:161-216`; called at `live_appworld.py:308`); the observation is classified by `error_kind` (`exec_calls.py:269-303`); observations are cut at `TRUNC=4000` (`exec_calls.py:137`; `run_appworld.py:213-217`). Change: methods `tasks(split)`, `open(task, seed)`, `step(code)`, `speculate(call)` (requote + save + step + restore + time guard, returning observation and error kind), `judge()`, `close()`; `requote`, `error_kind`, `err_tail`, `TRUNC`, the AppWorld seed and the no-code message live in `data/appworld.py`. Add `tests/test_rollback.py` from `selftest_shadow` (`live_appworld.py:841-872`), which is the only proof that speculation does not pollute the world.

## Loader must do

1. Load the raw YAML with `OmegaConf.load`, split it into `pipeline`, `common`, and the named settings; reject a file whose `pipeline` names a stage twice or outside the six.
2. Build the schema root with `OmegaConf.structured(Settings)` where every section is a nested dataclass created through `field(default_factory=...)`, optional sections (`probe`, `inject`, `score` for a baseline) typed `Optional[Section] = None`, and `notes: str = ""` as a real field.
3. Merge in order: schema, `common`, the named setting, `--debug` overlay, then `OmegaConf.from_dotlist(overrides)` last (the plan's order puts debug after the command line; reverse it). Struct mode on a structured config rejects unknown keys and wrong types on merge; list fields (`seeds`) are replaced, not appended, so `seeds: [42]` over `[42, 67, 4267]` gives `[42]`.
4. Resolve interpolations before anything is hashed or saved (`OmegaConf.to_container(cfg, resolve=True)`); `${models.probe}` resolves against the merged root, so a reference in `common` to a value set by the named setting works only after step 3.
5. Compute the diff against the resolved defaults recursively, dropping `notes`, and write it as `diff.yaml` and as a JSON field in the ledger row.
6. Compute a stage key from a canonical JSON dump (sorted keys) of: the stage's own section and the shared sections in the stage table (line 277-284), minus `sample.tasks`/`sample.seeds` (and their inject twins), plus the upstream keys, plus the upstream content manifest hash (finding 3), plus `VERSION`; twelve hex characters.
7. Resolve `<workflow>/<setting>` references (`inject.probe_score`, `score.baseline`) through the ledger to directories before keying, and fail loudly when the referenced run is not done.
8. Read `constants/*.yaml` for paths and the model table after keying, never before, so nothing in `constants/` enters a key.
9. Write `config.yaml` (resolved), `diff.yaml`, and return the object the stage code reads; a stage started as a subprocess piece reloads `config.yaml` from its run directory, so every piece's interpreter needs OmegaConf.
10. Validate that a debug overlay only touches fields the shape has, and that a baseline setting with no `probe` section does not receive one from `debug.yaml` (overlay `models.probe` only when the pipeline has train or inject).

With the dataclasses and their one-line comments, `settings/config.py` is 300 to 450 lines, not a short helper.

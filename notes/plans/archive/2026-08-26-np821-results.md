# np821 batch results report (wrapped up 2026-08-26)

States only facts. The setup and conventions are in `DATA.md`'s
nyapass_aw_v1 section and `TIMELINE.md`'s 2026-08-22 entry (max_bounds
kept at 64); process rulings (rulings 1-7) and the step-by-step record are
in `plans/2026-08-22-np821-exec-worklog.md`; the plan itself is in
`plans/2026-08-21-np821-plan.md`. All numbers are read from each run
directory's `train_log.jsonl` / `REPLAY_REPORT.json` /
`CALLGEN_REPORT.json` / `PARAM_REPORT.json`; the same numbers went into
`ops/runs.jsonl` and `RESULTS.md` via `run.py record finish`.

## 1. What this batch is

- The model being probed, gpt-oss-120b (appworld, collection run_id
  `nyapass`): temperature 1.0, 4 trajectories per task (seeds
  42/67/4267/6742 correspond to `_r0.._r3`), 315 tasks x 4 = 1260
  trajectories, 41 of them hit the 30-step cap.
- Dataset `nyapass_aw_v1/gptoss`: equal weight per step (w=1), max_bounds
  64; samples train 186479 / dev 115211 / test_normal 391893 (693583
  total); events train 4127 / dev 2556 / test 8533.
- Four training batches x three cells (ctool / cgen / cparam), backbone
  and training method:

  | Batch | Backbone | Training method | Card |
  |---|---|---|---|
  | np821b06 | Qwen3-0.6B-Base | full-parameter, no grad-ckpt | tokyo108 H100 x3 |
  | np821b17 | Qwen3-1.7B-Base | full-parameter + grad-ckpt | tokyo108 H100 (ctool/cparam gpu1/2; cgen took over gpu1) |
  | np821l17 | Qwen3-1.7B-Base | LoRA (r16/alpha32/dropout 0.05/lr 2e-4) + grad-ckpt | tokyo107 RTX 6000 Ada x3 |
  | np821l4 | Qwen3-4B-Base | LoRA (same as above) + grad-ckpt | tokyo108 H200 x3 |

  cgen/cparam's 3 epochs = 17484 optimizer steps (batch 32), ctool 387
  steps; max_len 4096 truncated from the left, max_tgt_tok 160, seed 42;
  at the end of every epoch, CE is computed over the full dev set plus
  200 generations; `best/` is taken by best_val_ce (cgen/cparam) or
  best_calA_weighted_acc (ctool).

## 4. Traceability anchors

- run_id: training `np821<batch>_gptoss_<cell>`, evaluation
  `eval_np821<batch>_gptoss_<cell>` (24 finish records in total).
- Each run directory's `RUNMETA.json` (the `launches` list) pins the
  launch commit and the actual command; each of the 12 training
  directories has two kind=train entries (one from the launcher, one
  manually added, with identical content, see the worklog's "root-cause
  fix" section).
- The evaluation code is the same version as the p1 batch; no separate
  evaluation smoke test was done (ruling 7, basis in the worklog).
- Measured duration (evaluation timed by event count): ctool's
  first-to-last heartbeat per batch is 36-45 minutes; a call-cell is
  21-26 minutes.

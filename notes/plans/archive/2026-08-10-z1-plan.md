# z1 batch plan: smallest scale rebuilt from scratch, for the §5 live-run smoke test, output deleted once tested

2026-08-10. User ruling: it's fine to deploy a very small-scale test from
scratch and delete the output once tested. This batch answers one question:
**can the three smoke acceptance lines in METHOD.md §5 (a fire must be
identifiable / R3 token comparison / empty-injection control) pass on the
current code?** It does not produce an accuracy conclusion; the probe is
trained on a tiny sample, so the numbers have no reference value.

## Phase 0, five variables

| Variable | Value | Note |
|---|---|---|
| BATCH | `z1` | run_id prefix |
| ENV | `appworld` | the official task set's three splits, ready-made |
| MODELS | `gptoss` | the current active setting (METHOD.md §1) |
| CELLS | `ctool cgen` | only train the two cells the live run needs; mtool/mext are not trained |
| DATA_ROOT | `/net/tokyo100-10g/data/str01_01/y-guo/reproduce/new1/pipeline/data/aw_z1_v1/gptoss` | goes straight to NFS (the big-output iron rule; this batch is fully deleted once tested, no home symlink is made) |

## Scale (very small)

- Collection: train 12 tasks / dev 4 tasks / test_normal 4 tasks, 20 tasks
  total, `--api harmony --start-date 2026-07-31` (= rebuild.COLLECT_DATE,
  the same date convention as /render and the vLLM pin), temperature 0.0,
  seed 20260729 across the whole chain.
- Training: ctool / cgen run the full data directly at this small scale
  (the data itself is already smoke-test scale, so no further `--smoke`
  subset is applied; ctool first runs `--align-only` to pass G13).
- Evaluation: only eval-tool-causal is run, to produce the REPLAY_REPORT
  (the live run only needs its temperature and logits; chosen_theta will
  likely be null at this small sample size, which doesn't matter, since
  theta is now always passed manually). eval-ccall is not run (the live run
  doesn't need CALLGEN_REPORT).
- Live-run smoke test: 2 tasks from test_normal, probe arm (theta manually
  set low to guarantee a fire, the value is recorded) + a --no-probe arm +
  the chat baseline, the three acceptance lines per §5.

## Three deviations from the standard pipeline (all because this is a smoke batch that gets deleted once tested, recorded here)

1. Not going through the gen-launch manifest (its client has no cap on task
   count); the collection client runs `run.py collect-aw --n <N>` directly
   in tmux; the vLLM server is still launched through the regular gpu-run
   `launch` with registration.
2. Skipping the G14 four-cell smoke test and the G8/G12 reproduction
   acceptance checks (G8/G12 assume "new code fed old data," and this batch
   has not touched annotate/eval, and the old data no longer exists to
   compare against). The G13 alignment check still runs.
3. Output goes straight to an absolute NFS path, no home symlink is made;
   once tested, `rm -rf` on the three directories leaves nothing behind.

# Three arms token-identical (ident3): plan

2026-08-18. gyb's request: make the three lines **token-identical**, then run
5 tasks, 10 repeats per arm per task, and look at the results. The three
lines:

| Arm | Name | How it runs |
|---|---|---|
| chat | chat baseline | `run_appworld.py --api chat` (the vLLM chat endpoint, server-side rendering + parsing) |
| noprobe | no probe | `live_appworld.py --no-probe` (/render produces the prefix ids -> completions decodes in one streamed shot) |
| nofill | probe but nofill | same path as noprobe, but at each step the stream is **interrupted** at one sentence-end cut, and the model's own generated token ids are appended to the prefix as is and refired to continue; nothing is injected. The probe weights have been deleted, so firing uses a fake rule (below). |

What "token-identical" means: the prompt id string fed to the engine by all
three arms is the same at every step (chat's prompt_token_ids ==
/render's prefix_ids, verified; nofill's refired head is the id the model
itself wrote, no longer going through text re-tokenization). Below this
layer, only server-side numerical noise remains (bf16 ties, cache/batch
composition), which was ruled "treat as noise" on 2026-08-18; this
experiment measures exactly that: how much the same arm differs across its
10 repeats, and whether the cross-arm difference is the same size.

## 1. Token-identical implementation

- The streaming request carries `return_token_ids: true` (supported by
  vLLM 0.26's completions; each chunk's `token_ids` and `text` are the
  increment for the same step), and the driver accumulates `raw` text and
  `gen_ids` together. **The streamed text lags behind the ids**: with a
  stop string, vLLM holds back `len(stop)-1`=9 characters and doesn't emit
  them (`detokenizer.py`'s `stop_buffer_length`; the smoke test measured
  decode(head) having an extra ` We have`), and it also holds back when a
  multi-byte character isn't complete yet; when generation outpaces
  consumption, several tokens get merged into one chunk. So chunk
  boundaries cannot be used as token boundaries, only as a starting point.
- Cuts: sentence-end cuts are found by their **start position**
  (`sent_starts`: the `m.start()` of `SENT_RE=(?<=[.!?])\s+|\n`, i.e. after
  the punctuation, before the whitespace). Using the start position rather
  than `m.end()`: the whitespace after a sentence end arrives in pieces
  (`. ` first, then `\n`), so recording by end would count the same
  sentence end as two cuts, and "the Nth cut" would shift with chunking;
  the start position doesn't move. The replay line's `sent_cuts` (by end)
  is left unchanged.
- head = **the shortest id prefix covering the sentence-end punctuation**
  (`find_head`: starting from the k0 estimated from chunk boundaries, check
  one by one with `/decode` to find the shortest k such that
  `len(decode(gen_ids[:k])) >= the cut's start position`): when `.` and
  ` Then` are separate tokens, head stops at `.`; when `.\n\n` is one
  token, it's included whole. This rule looks only at the model's token
  sequence, not at how the stream is chunked, and is reproducible across
  the 10 repeats. The shared part of the decoded text and the streamed
  text must match character for character; if they don't, it raises an
  error and stops (not silent); after refiring, `raw` is taken from
  decode(head). At the end of the step, `decode(gen_ids)` is checked
  against `raw` once more (recorded in the gen record as
  `text_ids_consistent`; a mismatch only warns, it doesn't invalidate the
  run).
- Refired prompt = `prefix_ids + head_ids` (nofill); once a NOTE is carried
  in the future it becomes `prefix_ids + head_ids + /encode(note)`, with
  the note encoded separately so the model's own last token doesn't get
  merged with it (this carries D14's approach over into the live run).
- Every interruption saves the ids generated past the cut and then
  discarded (`overflow_ids`); the first `len(overflow_ids)` ids from the
  refired continuation are compared to it position by position: this is a
  direct measure of whether a token-identical refire reproduces the
  model's own continuation (`overflow_match_len` / `overflow_identical`).
- chat arm: `return_token_ids: true` added to `extra_body`, and each step
  records `out_token_ids` / `prompt_token_ids` (behavior unchanged, only
  extra fields are stored), for token-by-token comparison.
- All three arms' gen records carry the whole step's token ids; scoring
  compares the first divergence position by id.

## 2. Fake trigger (the probe weights have been deleted)

`--fire-nth-cut N`: fires once at the Nth sentence-end cut of each step (in
`sent_cuts` order, after the `MIN_THINK//2` filter), without hitting
`/score` or `/gen`. Default N=5: across the 68 steps of the 5 tasks, the
median number of thinking sentence-ends is 25, the lower quartile is 7, so
the 5th cut exists in most steps (steps with fewer than 5 sentence-ends
don't fire, recorded as `n_inject=0`). `--nofill`: nothing is injected when
it fires (no speculate, no NOTE written). The two flags are independent: in
the future, a real probe + `--nofill` would mean "real trigger, nothing
injected."

## 3. Scale and concurrency

- Tasks: the first 5 test_normal tasks (the same set as
  `cmp_chat_noprobe_5`): 3d9a636_1/2/3, fd1f8fa_1/2.
- 10 repeats per arm per task: `<root>/<arm>/rep<r>/`, `--exp
  ident3_<arm>_r<r>` (AppWorld experiment directories can't share a name).
  150 whole-task live runs in total.
- Each of the three arms runs as its own process in parallel (within a rep
  the 5 tasks run serially, and reps run serially too); all three hit the
  same single vLLM replica. The last time, 5 tasks of chat serially took 11
  minutes, so with 3 arms in parallel this is estimated at about 2-2.5
  hours.
- Server: the same vLLM command as `splice_replay_v1_srv` (one H200 on
  tokyo108, `VLLM_SYSTEM_START_DATE=2026-07-31`), plus a render-only
  probe_server (CPU, `--render-only`, with `/decode` added).
- max_steps 20, max_tokens 8192 per step, effort high, temperature 0, same
  as cmp_chat_noprobe_5.

## 4. Metrics (`ident3_score.py` -> IDENT3_REPORT.{md,json})

1. Per task per arm: the success count across 10 repeats, the step-count
   distribution, the total generated-token distribution, the
   task_error/abort count.
2. Pairing the 30 same-task runs two by two: the first divergence step, and
   the first divergence token position within that step; report the
   median, split by **same-arm pairs** (chat-chat / np-np / nf-nf) and
   **cross-arm pairs** (chat-np / chat-nf / np-nf), and the count of pairs
   with "the whole task token-identical." If the same-arm and cross-arm
   distributions look the same, there is no difference to speak of between
   arms.
3. Prompt id check: the fraction of steps before divergence where chat's
   `prompt_token_ids` and noprobe/nofill's prefix are equal id for id
   (should be 1.0; if not, it's a pipeline problem).
4. nofill only: the fire count, the `overflow_identical` fraction per fire,
   the `overflow_match_len` distribution, the `dropped_chars` distribution,
   whether the decode check passed every time.
5. A facts table, no interpretation.

## 5. Decision points

| # | Decision | My choice | Alternative |
|---|---|---|---|
| E1 | The probe weights have been deleted, how does the nofill arm trigger | Fake rule: fire once at the 5th sentence-end cut of every step | The 1st (fires in almost every step, but head is extremely short); a random cut (not reproducible across 10 repeats) |
| E2 | Landing the cut on a token boundary | head = the shortest id prefix covering the sentence-end punctuation (changed after review: looks only at the token sequence, independent of stream chunking; the original draft, "fall back to the chunk boundary no later than the character cut," was inaccurate when a stop string holds back characters or multiple tokens merge into one chunk) | Fall back to the nearest boundary no later than the character cut (also pulling in a standalone whitespace token, which is chunking-dependent) |
| E3 | Refire check | if the shared part of the decoded text and the streamed text is not equal, raise an error and stop the run; at the end of a step, decode(gen_ids) vs raw is only recorded, not raised | Silently back off one token and retry |
| E9 | Counting sentence-end cuts | by `m.start()` (added after review: recording by end would count the same sentence end twice as its whitespace gets chunked, and "the 5th" would shift with chunking) | By `m.end()` (the replay line's convention) |
| E10 | Step budget | `8192 - the number of ids kept` (discarded overflow doesn't count against the budget; for chat, all 8192 in a step are kept) | `8192 - all generated tokens` (nofill would hit the length cap early) |
| E11 | Pre-launch gate | `ident3_gate.py`: chat's `prompt_token_ids` == `/render`'s ids one for one; if not equal, refuse to run the whole arm (pins the vLLM date and return_token_ids) | Don't check (if vLLM's date isn't pinned, all three arms run to completion and the report gives no way to see why) |
| E12 | Scoring exclusion | if any arm's abort is non-empty, it's excluded from pass/fail and pairing (chat's `stepN:Err`, live's `task_error:*`, hitting the cap, no final) | Exclude only `task_error:*` (chat's failed runs would enter pairing as short trajectories) |
| E13 | Prompt check | compare by sha1 of the ids (chat stores the whole prompt_token_ids, live stores prefix_sha) | Compare only the token count (a different date can still have the same length, so this wouldn't catch it) |
| E4 | Three arms in parallel or all serial | Three arms in parallel, serial within each arm (~2.5h) | All serial (~6h; less batch-composition noise, but production already has batching) |
| E5 | Change to the chat arm | Only add the `return_token_ids` recorded field, no behavior change | Leave it untouched (then chat couldn't be compared token by token) |
| E6 | Tasks | Reuse the same 5 tasks as cmp_chat_noprobe_5 | Swap in different 5 tasks (wouldn't connect to the old data) |
| E7 | NOTE's leading newline (not run in this batch, code change only) | If head ends in whitespace, don't add `\n` (D5') | Always add `\n` |
| E8 | Overflow comparison | Store the discarded ids, compare position by position with the new ids at the same position after refiring | Don't store them (then only task-level results could be seen) |

## 2026-08-18 Three arms token-identical (ident3_v1): live-run refire switched to the model's own token ids, 5 tasks x 10 repeats to measure noise

- Trigger: gyb asked for chat baseline / no probe / probe-but-nofill to be
  made token-identical, 5 tasks with 10 repeats per arm per task to look at
  the results. The probe weights had already been deleted, so the nofill arm
  used a fake trigger (fire at the 5th sentence-end cut of every step,
  interrupt, refire with the model's own ids, insert nothing).
- Decision (implementation level, plan `plans/2026-08-18-ident3.md` §5
  E1-E13): the live-run stream carries `return_token_ids`; a fire-and-refire =
  prefix + the model's own generated id[:k] + a separately encoded NOTE, no
  longer re-tokenizing the whole text; head = the shortest id prefix covering
  the sentence-ending punctuation, cuts counted by their start position (both
  look only at the token sequence, not the stream's chunking; vLLM holds back
  9 characters when there's a stop string and doesn't emit them, and merges
  multiple tokens per chunk when generation is fast, so chunk boundaries are
  not token boundaries); the step budget is counted from the ids that remain;
  before launch a gate checks that chat's prompt_token_ids equal /render's ids
  one for one.
- Facts (`ident3_v1`, RESULTS.md; `.../runs/ident3_v1/IDENT3_REPORT.md`): 150
  runs, 0 failures; cross-arm prompt id sha equal 1780/1780 (that the three
  arms feed the engine token-identical prompts now holds); of 2175 same-task
  pairs, none has the whole task token-identical, each task has 10 different
  trajectories per arm across 10 repeats; the share of first divergence at
  step 0 is, for same-arm pairs, chat-chat 137/225, noprobe-noprobe 144/225,
  nofill-nofill 131/225; cross-arm chat-noprobe 308/500, chat-nofill 499/500,
  noprobe-nofill 496/500; successes chat 14/50, noprobe 13/50, nofill 20/50;
  of nofill's 564 interrupt-and-refires, 534 (0.947) reproduced the discarded
  overflow tokens bit for bit. The three arms hit the same replica in
  parallel (batch composition kept changing).
- Relation to the previous entry, "treat server-side numerical jitter as
  noise": these numbers are that layer of noise measured over whole tasks;
  even within the same arm, all 10 repeats already differ from each other, so
  arm-to-arm comparison can only rely on task count.
- Not done: a live run under a real probe (the probe needs retraining first);
  nofill and noprobe's first divergence is almost all at step 0, while
  same-arm pairs are only about six-tenths; this difference has not been
  analyzed, the fact is recorded for now.

## 2026-08-18 New project: splice replay (splice_replay_v1), how to splice the result back in when the probe fires, first measure a single step from a god's-eye view

- Trigger: comparing with-probe refired prompts against no-probe turned up a
  re-tokenization seam: the NOTE's leading `\n` merges with the model's
  `.\n\n` into one token (newline cuts mismatch 3558/3865, whitespace cuts
  all match); this raised the question of which way of splicing the result
  back in is actually best. The probe weights had already been deleted
  (`c1_gptoss_*`), so a live run could not be started.
- Decision (gyb): don't wait for the probe, use 5 chat baseline trajectories
  for a god's-eye replay: 52 single-call steps x sentence-end cuts at
  66/75/80/100% of the thinking x ten arms (4 in-thinking wordings + a system
  preamble / force-cut into the body after splicing x2 / fake a whole turn
  that drops the thinking / harmony's native python tool), each trajectory
  only continued one step, not run to completion, not evaluated, and not
  judged for prediction correctness. The four cut-ratio points were set by
  gyb.
- Decisions D1-D14 are all in `plans/2026-08-18-splice-replay.md` §6 (seam
  fix D5': when head ends in whitespace, no leading newline is added; n1
  wording changed to splice in the raw code-block text, D13; `<|call|>` is
  eos, all arms stop there, D11).
- Result: `splice_replay_v1_srv` (RESULTS.md);
  `.../pipeline/inject/runs/splice_replay_v1/SPLICE_REPORT.md`. The two
  splicing methods that degenerate under the god's-eye view (faking a whole
  turn that drops the thinking = skipping to the next step; the result
  arriving with the next turn = baseline) were not run.
- Not done: a live run under a real probe (the probe needs retraining
  first); wiring the winning splice method into live_appworld.

## 2026-08-18 Ruling: treat server-side numerical jitter as noise, stop chasing bit-for-bit reproduction

- Trigger: `cmp_chat_noprobe_5_srv4` measured 7 cold/warm divergence
  positions; the top-1/top-2 logprob gaps were all 0, 0.125, or 0.25 (one
  bf16 logit step is 0.125), and 6 had at least one state in an exact tie; at
  the same position across the two states, the top-1 logprob gap was <= 0.17
  nat. The divergence occurs at positions where the model itself cannot tell
  the candidates apart; it's a property of the server's bf16 plus cache-hit
  count deciding the numerical path, not a property of the arm; the seed is
  useless for argmax.
- Decision (gyb): treat it as noise. Do not run the "disable prefix caching +
  serial" reproduction check, do not chase bit-for-bit identity between the
  two arms; comparison between the two arms relies on task count to average
  out this layer of noise. The previous hold, "no scaling up before this is
  settled," is lifted.
- Not verified, recorded for the record: whether "disable cache + serial" is
  bit-for-bit stable within the same process; whether it is stable across
  process restarts.

## 2026-08-18 Five-task live run: the divergence between no probe and chat baseline comes from prefix-cache state, not from the endpoint

- Trigger: `cmp_chat_noprobe_5` (a single gpt-oss-120b replica on tokyo108,
  `VLLM_SYSTEM_START_DATE` pinned to 2026-07-31; each arm ran the first 5
  test_normal tasks, serially, one request in flight at a time).
- Facts: for all 5 tasks, the step-0 prompt token count is equal between the
  two arms (341/341/341/336/337); for 3 tasks the step-0 output already
  differs, for 2 tasks divergence only starts at step 2/3; pass/fail is chat
  3/5, no probe 3/5, on different tasks. Hitting the same prompt repeatedly:
  with a warm cache, completions(ids) and chat are bit-for-bit identical;
  after clearing the cache, a refire differs from the warm result (13/13),
  while within each of the cold/warm states the two endpoints are
  bit-for-bit identical with each other (13/13). The three tasks whose
  step-0 output looked "off" in the chat run were exactly the ones where
  that prompt was hitting the server for the first time (a cache miss).
- Decision: aligning no probe and chat baseline's conventions stops here for
  now (rendering / sampling / stopping / splitting are already identical
  layer by layer); for the two arms to be comparable, the next step is to
  force the server state to be consistent (candidates:
  `--no-enable-prefix-caching` + serial; `VLLM_BATCH_INVARIANT=1` doesn't
  come up for MXFP4, ruled out). Do not scale up before this is settled.
- Output: `/net/.../pipeline/inject/runs/cmp_chat_noprobe_5/{chat,noprobe,analysis}`;
  ledger entries `cmp_chat_noprobe_5_srv{,2,3}`.

## 2026-08-18 no probe's prompt switched to the same token ids as the chat endpoint, the three arms get names

- Decision: any difference between no probe and chat baseline that the code
  can align is aligned to the chat endpoint: `/render` no longer goes
  through jinja to produce text, it now copies the vLLM chat endpoint's
  rendering to output token ids directly, and the driver sends the prompt as
  a list of ids; chat baseline's `--reasoning-effort` default changed to
  high, and a per-task fallback handles single-task anomalies. The
  server-side numerical jitter from batch composition is outside what the
  client side can align; that's left for trying `VLLM_BATCH_INVARIANT` at
  launch time.
- Basis: on the same day, checked the vLLM 0.26.0 source layer by layer and
  tested it directly; the jinja text path is misaligned with the chat
  endpoint at two points (an assistant turn with empty content gets dropped
  entirely by the chat endpoint; a literal `<|...|>` marker in the content
  gets picked up by the completions endpoint as a real special token); once
  either is triggered, every subsequent step's prompt is permanently off;
  the other layers (sampling parameters, stop tokens, output splitting,
  environment seed) match code for code. Details are in `METHOD.md` §2.1 and
  §6-⑤⑥, judged by the test `tests/test_harmony_render.py`.
- Naming: chat baseline / with probe / no probe (`CONTEXT.md`, same day).
- Relation to the old record: when `awdiag_job.sh` investigated "live-run
  noprobe 17.3% vs w0 28.6%" on 2026-08-02, the two misalignments above, the
  `\n\n` rendering difference, and the unpinned date on the chat side were
  all still present, so that set of numbers cannot be attributed to a
  single cause.

Token Accounting Cheat Sheet

With prefix caching on, "how long is the prompt" has three different answers. This card spells out where each number comes from, which one we store, and what needs to change to get another.

Three numbers, don't mix them up

NameWhat it isWhere to get itDo we store it
SentThe full length of the entire promptusage.prompt_tokens in the responseStored (usage.in)
RecomputedThe part that actually went through the modelRequires --enable-prompt-tokens-detailsNot stored
HitThe part taken directly from existing KVSame as above, prompt_tokens_details.cached_tokensNot stored

The relationship between the three is hardcoded in the engine, at v1/metrics/stats.py:288:

Recomputed = Sent − Hit

num_computed_tokens = num_prompt_tokens - num_cached_tokens

Two fields in the server log

FieldWhat it countsWhere the definition is hardcoded
Avg prompt throughputCounts only what's recomputed, not what's hitv1/metrics/loggers.py:146-147
Prefix cache hit rateA token hit rate, not a request hit ratev1/metrics/stats.py:119, 141
↑ its windowThe most recent 1000 requests, slidingv1/metrics/stats.py:38, 42
The hit rate is a sliding-window value, not a cumulative one. Two percentages printed by the same service at different times cannot be compared as "the average hit rate for the whole experiment." To get a whole-run figure, you have to aggregate by request yourself.

One command to see the current hit rate

grep -o "Prefix cache hit rate: [0-9.]*%" <log> | tail -1

To see the trend over a stretch of time:

grep -o "Prefix cache hit rate: [0-9.]*%" <log> | uniq -c | tail -20

To store "how much got recomputed," two places need to change

Adding half of it is the same as not adding it. Only when the server side passes --enable-prompt-tokens-details can the client read prompt_tokens_details.cached_tokens; changing only the client will always read None, and changing only the server means nobody stores it. If you add it, do the full three-piece set: change the code + register it in run.py + write back to the skill, all in the same commit.

This repo currently stores token usage in two places: envs/collect/common.py:68 and :89 (the collection pipeline's raw / chat paths), and pipeline/inject/replay_inject.py:818 (the injection pipeline). All three store the full length.

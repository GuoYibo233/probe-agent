# research-loop 插件开发计划（2026-08-16 两轮讨论后的定稿状态）

上午一轮逐步确认锁了六个裁决和五块架构，下午 gyb 用语音又打磨了一轮。这份文档是两轮合并之后的现状，往后施工以这份为准，和 redesign.md 冲突的地方以这份为准。

## 目标与总验收

先把共同底座和交流用的 json 落进插件，落完之后才写五个角色的 SKILL.md。总验收由 gyb 定：每个角色配一个对应的任务，两个 agent 一个加载角色 skill、一个不加载，各做一遍，产出摆在一起由 gyb 自己看，不预先定判分办法。

## 五个角色

idea 和 gyb 交流想法，出工单派给 deploy。deploy 写代码（把探索性概念转成清晰可发布的实现），把怎么运行交给 run。run 看服务器、运行实验、主要负责长时间的任务，出问题要回报。reviewer 审查整条链路有没有照定好的执行。analysis 分析实验结果、画图。

每个角色由两份文件定义：一份 SKILL.md，一份 json。json 里三样：能读哪些记忆、能干什么事、能给谁派活。五份 json 合起来就是分权表本体，钩子按角色读自己那份。

文献这条线（gyb 2026-08-16 语音裁定）：把文献变成 idea 这件事只有 gyb 亲自做；idea 角色要经 gyb 允许才有读文献的权限；reviewer 永远不读文献、不猜 gyb 的意思，审查基准只有 gyb 定下的决定。

reviewer 的三条特殊规矩（gyb 同轮裁定）：
1. 他审的是「gyb 和 idea 层谈定的东西有没有被好好执行」，具体三样：代码写得对不对、实验运行得对不对、analysis 写的分析代码和 notebook 是不是 gyb 要的。他审分析代码，不碰数据统计本身，统计是 analysis 的活。
2. 对抗性隔离：不读 deploy 的想法，只读 idea 的决定和最终的代码，从不知道实现者怎么想的位置对抗着查。这条靠纪律写进 SKILL.md，不上钩子（gyb 裁定，「读权一律不硬拦」无例外）。
3. 产出放单独的 review/ 文件夹，问题清单就放在这里，不进 notebook。

## 账本

账本一共八本，全放 loop/，一行一条 json（不用 markdown），只经 bin/rl 命令进出，只增不改：

1. decisions，决定账，按五个角色拆成五个文件（gyb 裁定，五个 session 并行各写各的不撞车）。
2. issues，问题条：干不了、不归我干、被钩子拦了，开一条等上游或 gyb 回。
3. handoffs，派活单：工单和发射单同一本账，用 work_type 区分。
4. runs，数字账，一个 schema，只有 run 角色的脚本能写。
5. grants，授权，只有 gyb 能写。
6. feedback，反馈账，谁都能提、只有 gyb 能裁。
7. evaluations，口径账，一行一个指标，analysis 提案、gyb 批准后才生效。
8. sessions，会话账（2026-08-16 语音新加）：哪个会话、什么角色、几点开始、几点销号。

行格式的公共骨架五样：主键、时间、写这行的角色、内容字段、schema_version。每一版另记写入会话的 session_id。

决定账的结构是一棵引用树：
- 编号带角色前缀（dec-idea-0007），更新不换编号、版本号加一。默认读取对每个编号只取最新版，历史全在文件里但默认读不到，要旧版本用专门的历史命令。superseded_by 退役，废除等于追加一版标 retired。
- 两个旧决定可以合成一个新决定：新决定拿新编号，来源引用字段允许指多条旧决定，旧的各追加一版标 retired。
- 跨层引用带版本（「依据 dec-idea-0007 第 2 版」）。引用记的版本比账里最新版小就是过时，查询命令当场标出「上层依据已从第 2 版更新到第 3 版，复核这条还成不成立」。角色上线第一个动作跑过版检查。

## 交接与会话生命周期

派活单五个状态，每个状态只能由固定的人写进去：待干（上游开单时写）、开干（下游接活时写）、卡住（下游写，必须连带开 issue 互相引用，谁回了 issue 谁捞回开干）、干完等待验收（下游写）、验收完成（只有上游写，验收人必须是派活的人）。验收不过不加新状态，上游打回开干并写明原因。状态转移的合法性由入账脚本当场校验。

派活必须带解释：idea 给 deploy 的工单里不能只甩决定编号，还要附一段 idea 自己写的解释，把那条决定里的东西讲明白。

交接由程序盯着，不许有去无回（gyb 语音裁定）：rl status 现场汇出所有没走到验收完成的单子，谁手上、卡在哪个状态、挂了多久。上游可以收回：对派出去还没干完的单子追加一版标收回，单子关闭。

会话生命周期：加载 skill 把角色分配给会话的那一刻算开始，钩子看得见这次加载，自动登记进 sessions 账。结束两条路：agent 干完活自己调一条结束命令销号，或者 gyb 手动结束。销号时程序当场检查这个会话名下有没有还挂在开干的单子，有就不许悄悄下线，要么交回待干让别人接，要么标卡住开 issue。一个会话只加载一个角色。

## 分权与钩子

写权硬拦，按路径判：experiments/ 只有 deploy 能写，analysis/ 只有 analysis 能写，review/ 只有 reviewer 能写，产物根只有 run 的任务能写，loop/ 谁都不许直接 Write/Edit，八本账只能经 bin/rl。每本账内部谁能追加哪种行，由入账脚本按上面两节的规矩校验。读权一律不硬拦，靠纪律。

钩子跟角色绑定，先有角色才有钩子：钩子写在角色 SKILL.md 的头部，加载角色的那一刻装上，不存在「用钩子去认角色」这回事（机制 2026-08-16 已实测：加载前不拦、加载后拦、拦的时候模型收到钩子写进标准错误的原话）。

钩子的回话要指路（gyb 裁定）：拦下越权用 deny，同时告诉模型你是谁、为什么拦、去开 issue 的命令是什么。读失败之类的场合同样要返回合理的下一步建议（换个办法、还是发给哪个角色），学 Claude Code 工具调用失败时的回话方式。

读的纪律写进每个角色 SKILL.md 的读法栏，公共母版里的原话方向：读文件先想清楚要回答什么问题，再挑最小的读法。读进来的每个字都留在上下文里挤占后面的判断，所以大文件禁止整读，抽查实验输出就是抽几条看文字形态，日志用 grep 和头尾定位。读记忆只读自己需要的那部分、默认最新版。对污染上下文大的读操作特别警惕。

## 两棵树

init 在研究仓库里建的（五样）：research-loop.json 配置（各账路径、产物根、本仓库跑法）、loop/ 八本账、experiments/ 运行实验的代码、analysis/ 统计代码和 notebook（公共统计件由 init 播模板，notebook 由 analysis 干活时新建）、review/ reviewer 的产出。原始数据不新建目录，走配置里的产物根，在 new1 指到 net 盘。

插件本体：skills/ 六个（入口加五个角色）、common/ 公共母版（通例九条、词表、五栏规格）、tables/ 和 schemas/（八本账的表结构和行格式）、scripts/ 入账与查询的实现、bin/rl 命令入口、hooks/ 钩子脚本本体（五个角色共用一个脚本、参数报角色名，落不落得下见待验证）、monitors/ 两个（发射看门狗只在 run 上线时起、反常结果预警盯数字账）、tests/。

## 入口 skill

留下，只负责 init 和领路，明写「本 skill 不干活」。只许 gyb 手动调用，永远不许模型或其他东西调用（候选机制是 skill 头部声明禁止模型调用，待验证）。

## 待验证清单（gyb 裁定：讨论全部收口之前一律不测）

1. Bash 环境里有没有现成的会话 id 变量；没有就用 SessionStart 钩子写状态文件。
2. skill 头部声明钩子能不能给命令带参数（五个角色共用一个钩子脚本靠它）。
3. monitor 的 when: "on-skill-invoke:run" 写法实测行不行。
4. skill 头部禁止模型调用的声明，能不能把入口 skill 锁成只许 gyb 手动调用。

## 挂起的步骤

完整流程纸上走查（拿「idea 出主意到数字进账」这条链查断点）还没有走，gyb 要先自己打磨设计文档。之后的施工步骤照旧：写架构文档（一个文件一行）、施工第一段共同底座、第二段交流用的 json、三个 session 并行写 SKILL.md、装上跑通最小一条路、总验收对比。

## 讨论中改掉的方向

1. 补齐资产盘点这一步撤掉了。gyb 裁的：先把目标画明白，再拿着图去现有代码里点名挑件，点不到的不花时间判。昨天 74 件判定被推翻 20 件，就是因为拿着没画完的图判库存。
2. 「读 transcript 认角色」这条验证路线废弃，被 skill 头部钩子取代。
3. 「一个决定更新就换新编号加 superseded_by」废弃，被「编号不变加版本号」取代，理由是下层引用不会挂在旧版上。
4. 六个裁决里「决定账一个字段不拆文件」的旧倾向被 gyb 推翻，拆成五个文件。
5. reviewer 不管文献这条上午锁过，下午 gyb 把整条文献线说全了：文献变 idea 只有 gyb 亲自做，idea 读文献要经允许。「这个想法别人做过没有」仍然没有角色管，要加文献账是另一件事。

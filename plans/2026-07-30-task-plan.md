是否存在,存在则不重跑）;`python ops/gpu_jobs.py watch` 与实际 tmux/显存对账。
**验收**:一份对账清单,每个在飞任务有归属和状态;发现的孤儿任务/漏登记列出处理建议。

**验收**:200 任务结果文件生成且 build_dataset 能解析出事件;台账与 record 双登记;服务杀净,显存归零。

### T2 v3 主线评测（卡｜依赖 v3 三训毕,归属由 T0 查清）

### T4 eval_replay 换算段（程序,小｜无依赖,应赶在 T2 之前合入）
目的:落实项目价值主张——卖点是省 token 和降延迟,不是预测准;每份评测报告必须自带这笔账,
否则论文主图(省 token 曲线 vs 准确率损失曲线)的数据要事后补算,且汇报口径会跑偏回"只报精度"。
注意:此处是离线估算,与 T10 的 fork 对照(在线实测)量的是同一个量——省 token;
两路数字对账是论文的交叉验证结构,报告格式设计时字段口径要对齐,便于日后并排。
给 `envs/bert/eval_replay.py` 报告加两个派生数:期望省 token 比例（≈触发率×提前量,
分 θ 档报）和期望重叠延迟。纯 CPU 后处理。
**验收**:REPLAY_REPORT.md 新增换算表;旧字段一个不动;拿 bfcl_v2fix 旧数据重跑,原有数字逐位不变。

### T5 消融两件（程序+卡｜依赖 v3 数据 + T2 出参照数字）
目的:信号来源分解。回答审稿人必问的"是不是光看历史就能猜"(no-think),并给加速架构画分布——
零思考时刻就能预测对的事件占比,决定"思考开始前就发预测"这条最省的产线值多少;no-hist 量
思考单独的价值。删掉此任务,论文核心主张(思考文本携带增量信号)无消融支撑。
给 `envs/bert/train_probe.py` 加 `--input-mode {full,no-think,no-hist}`:
no-think 切 [THINKING] 段（同事件样本合并为一条,权重归一）;no-hist 切 [HISTORY] 段。
训练:no-think 三环境（每个几分钟）+ no-hist 三环境（每个 1 卡 2-3h）。
评测:no-think 报 test 普通准确率（回放协议退化,每事件读一次）;no-hist 走完整评测。
**验收**:模式开关有单测级验证（打印三种模式各一条样本肉眼核对切割正确);六个训练完成;
一张信号分解表:历史单独/思考单独/合流,三环境齐,对照 v3 主线数字。

### T6 跨模型双向矩阵（程序+卡｜依赖 v3(tales/appworld 部分) 与 T3(bfcl 部分)）
目的:部署结论——换 agent 模型,探针是原样能用、重做校准即可、还是必须重训;双向矩阵
同时裁决"强模型轨迹训弱模型上用是否更好"这个用户提出的假设。掉分大也是诚实的局限,照写。
按样本 `model` 字段过滤:qwen 系（qwen3.5/3.6）与 gpt-oss 两侧,训练侧×考试侧四格。
每格两种校准都报:冷迁移（校准用训练侧数据）与只换校准（校准用考试侧 calA/calB,纯 CPU）。
**验收**:每环境一张 2×2 矩阵（bfcl 等 T3）;附三分数对照:主场成绩/客场成绩/混训天花板;
过滤逻辑有验证（各侧事件计数与预期一致,qwen 训练侧 tales≈920/appworld≈1426 事件量级）。

### T7 抽取头（程序大+卡｜依赖 v3 数据;评测联动依赖 T2 的评测协议现行实现）
目的:把投机从"猜对工具名"升级到"完整调用提前备好"——没有参数,预取和截断都只是半成品;
选择档(约 76% 事件)是参数产线主力,它的正确率直接决定投机覆盖面;对标竞品 SPORK 参数
起步 7.6% 的弱点是论文卖点之一。T10 闭环依赖它当选择档产线。
三件套:①标签脚本——每事件每参数,在样本 text 里定位参数值子串（多处取最靠末尾一处;
定位不到标"抽不到"）;②模型——ModernBERT 加第二个头,输入拼"工具名.参数名"指明所找参数,
输出起止位置,须支持输出"抽不到";③评测——先跑回放定出每事件首次过 θ 的触发位置,
抽取头在该前缀上抽,值尚未出现即记失败。
**验收**:标签脚本抽样 50 条人工核对定位正确;报触发时刻参数全对率与完整调用正确率
（=分类对×参数全对）,分三档;锚点对照:竞品 SPORK 参数起步正确率 7.6%,选择档应达九成量级;
已知风险写明:早期触发点参数常未出现（先行试点数据:提前 25 token 时字面串仅 33.8% 已出现）。

### T8 因果探针（程序+环境+卡｜依赖 v3 数据;权重下载/环境无依赖可先行）
目的:部署形态裁决。ModernBERT 每探一次重编码整个前缀,成本随思考长度平方涨,探得勤是
提前量的来源,所以这是分水岭问题不是优化问题;因果探针增量编码把总量降到线性,还附带
自由档参数的生成能力。产出"分类差距 vs 探测成本"两个数,定 v2 部署形态用谁。
①下载 Qwen3-0.6B-Base 与 LFM2.5-350M-Base 到 NFS 模型目录（env-runner 干,不占卡）;
②LFM 需新环境 cprobe-env（transformers≥5.2,uv 管理）;③新训练脚本:因果语言模型+分类头,
整段一次前向、每个句子边界位置放分类监督;④**铁律:开训前过对齐检查**——同一段文本,
整段一次前向 vs 按句分块增量前向,末位置 logits 逐位一致才许训（混合架构在缓存非空+一次
喂多 token 场景有静默算错前科）;⑤两底座各训三环境或先 bfcl 探路(执行者按卡情裁量,汇报写明)。
**验收**:对齐检查通过记录;评测与 ModernBERT 完全同轨可并排;交两个数:分类差距、
探完一条轨迹的计算量对比;LFM 许可非 Apache,汇报如实标注。

### T9 闭环管线（程序,全项目最大工程｜不依赖任何实验,建议立即动工）
目的:此前一切数字都是离线回放的估算,审稿只认真实计时;管线是把探针放进真运行的唯一
通道,是 T10 的全部基建,也是全项目日程瓶颈——它晚一天,关键图和 C4 全晚一天。
拦 agent 的 token 流→切句→每句喂探针→过 θ 触发→按口径分动作。管线须支持五个口径
(定义见 T10):截断/预取/影子记录/fork 对照/基线。fork 对照的工程要点:触发处复制完整现场,
分支内探针关闭(铁律,防递归),分支走完任务后记 token 账与成败;需要环境状态可复制——
bfcl/appworld 的模拟状态可行,tales 游戏引擎能否存档**待调研,是本任务的已知工程风险**。
计时基建:墙钟/token 账单/任务成功率三表,serving 侧对照（基线组与实验组同服务配置,
单独量探针开销）。
**验收**:单任务端到端演示跑通（bfcl 一个任务,截断+影子记录+fork 对照各演示一次,日志能
看到触发位置、提交的调用、与 agent 本意调用的核对结果、fork 分支的 token 差）;
计时数字可复现;探针开销单独成列。

### T10 闭环正式跑分（卡,大｜依赖 T9 + v3 探针 + T7）
目的:产论文关键图的数据——真实计时下省 token/省墙钟 vs 任务成功率损失,θ 扫出整条曲线;
这是"省 token 和降延迟"价值主张的最终证据,回放估算(T2/T4)只是它的预告。
三环境（顺序 bfcl→appworld→tales 已批准）×五口径（用户 2026-07-30 定稿）:
① **基线组**:不带探针,agent 原样跑,总账下限;
② **截断组**:全程用我们的方法,触发即掐断提交,θ 从松到紧扫数档;
③ **预取组**:只读调用后台先执行,agent 自发调用时核对递上;限 bfcl/appworld,tales 不做
   （游戏环境后台执行等于偷跑）;
④ **影子记录**:agent 正常跑,探针只记"此刻会提交什么"不执行,事后与真实调用对账——
   零风险零额外算力,全程开启,是回放协议的线上验证;
⑤ **fork 对照**:每个触发事件在首次过 θ 处复制现场 fork 一次（上限一次,分支内探针关闭）,
   分支走投机路线到任务结束,与主线对比 token 账与成败——每事件一对因果对照,
   实测省 token,与 T4 离线估算对账。成本约使生成量翻倍,tales 上若过贵回用户处砍量。
**验收**:关键图数据齐——横轴任务成功率损失、纵轴省 token(和省墙钟),θ 扫出曲线;
影子记录的线上精度与离线回放评测对账;fork 对照的实测省 token 与 T4 估算对账;
带 serving 对照;每组多种子,报置信区间。

### T14 C4 会师（卡,最后｜依赖 T10 + T13）

# 三臂逐 token 同（ident3）——计划

2026-08-18。gyb 的要求：把三条线做到**逐 token 同**，然后 5 道题、每题每臂各跑
10 遍，看结果怎么样。三条线：

| 臂 | 名字 | 怎么跑 |
|---|---|---|
| chat | chat baseline | `run_appworld.py --api chat`（vLLM chat 端点，服务端渲染+解析） |
| noprobe | no probe | `live_appworld.py --no-probe`（/render 出 prefix id → completions 一枪流式解码） |
| nofill | probe but nofill | 同 noprobe 路径，但每步在一个句尾切口**中断**流，把模型自己生成的
  token id 原样接在前缀后重发续写；什么都不塞。探针权重已删，触发用伪规则（下）。 |

"逐 token 同"的含义：三臂喂给引擎的 prompt id 串在每一步都相同（chat 的
prompt_token_ids == /render 的 prefix_ids，已验；nofill 重发的 head 是模型自己写的
id，不再经文本重分词）。这层之下只剩服务端数值噪声（bf16 平局、缓存/批组成），
2026-08-18 已裁"当噪声"，本实验就是量它：同臂 10 遍之间差多少、跨臂差是不是
一样多。

## 1. 逐 token 的实现

- 流式请求带 `return_token_ids: true`（vLLM 0.26 completions 支持；每块的
  `token_ids` 与 `text` 是同一步的增量），驱动器同时攒 `raw` 文本和 `gen_ids`。
  **流文本比 id 落后**：有 stop 串时 vLLM 压着 `len(stop)-1`=9 个字符不吐
  （`detokenizer.py` 的 `stop_buffer_length`；smoke 实测 decode(head) 多出 ` We have`），
  多字节字符没凑齐时也压；生产快过消费时几个 token 并成一块。所以块边界不能当
  token 边界用，只当起点。
- 切口：句尾切口按**起点**找（`sent_starts`：`SENT_RE=(?<=[.!?])\s+|\n` 的 `m.start()`
  = 标点之后、空白之前）。用起点而不是 `m.end()`：句尾空白是一段段到的（`. ` 先到、
  `\n` 后到），按 end 记同一句尾会算成两个切口、"第 N 个切口"随分块变；起点不动。
  回放线的 `sent_cuts`（按 end）保持不动。
- head = **盖住句尾标点的最短 id 前缀**（`find_head`：从块边界估的 k0 起，用 `/decode`
  逐个核，找最短的 k 使 `len(decode(gen_ids[:k])) ≥ 切口起点`）：`.` 与 ` Then` 分开时
  head 止于 `.`；`.\n\n` 是一个 token 时连它一起。这个规则只看模型的 token 序列，
  不看流怎么分块，10 遍之间可复现。decode 文本与流文本的公共部分必须逐字相同，
  不等就抛错停（不静默）；重发后 `raw` 以 decode(head) 为准。步末再核一次
  `decode(gen_ids)` 与 `raw`（gen 记录 `text_ids_consistent`，不一致只告警不作废）。
- 重发 prompt = `prefix_ids + head_ids`（nofill）；将来带 NOTE 时 =
  `prefix_ids + head_ids + /encode(note)`——note 单独编码，模型自己的最后一个
  token 不会被合并（D14 的做法搬进活跑）。
- 每次中断把切口后已生成、被丢弃的 id 存下（`overflow_ids`），重发续写出来的前
  `len(overflow_ids)` 个 id 与它逐位比：这是"token 同的重发是否复现模型自己的续写"
  的直接量（`overflow_match_len` / `overflow_identical`）。
- chat 臂：`extra_body` 加 `return_token_ids: true`，每步记 `out_token_ids` /
  `prompt_token_ids`（行为不变，只多存字段），供逐 token 比对。
- 三臂 gen 记录都带整步的 token id，打分时按 id 比首个分叉位。

## 2. 伪触发（探针权重已删）

`--fire-nth-cut N`：每步第 N 个句尾切口（`sent_cuts` 顺序、`MIN_THINK//2` 过滤后）
开火一次，不打 `/score` `/gen`。默认 N=5：5 题 68 步的思考句尾数中位 25、下四分位 7，
第 5 个切口在多数步都存在（不到 5 个句尾的步不开火，记 `n_inject=0`）。
`--nofill`：开火时什么都不塞（不 speculate、不写 NOTE）。两个旗标独立：将来真探针
+ `--nofill` 就是"真触发、不塞"。

## 3. 规模与并发

- 题：test_normal 前 5 题（与 `cmp_chat_noprobe_5` 同一组）：3d9a636_1/2/3、fd1f8fa_1/2。
- 每臂每题 10 遍：`<root>/<arm>/rep<r>/`，`--exp ident3_<arm>_r<r>`（AppWorld 实验目录
  不能重名）。150 次整题活跑。
- 三臂各一个进程并行（各自 rep 内串行 5 题、rep 间串行）；同一 vLLM 单副本。
  上次 5 题 chat 串行 11 分钟 → 估 3 臂并行 ≈ 2–2.5 小时。
- 服务：`splice_replay_v1_srv` 同款 vLLM 命令（tokyo108 一张 H200，`VLLM_SYSTEM_START_DATE=2026-07-31`），
  render-only probe_server（CPU，`--render-only`，加 `/decode`）。
- max_steps 20、每步 max_tokens 8192、effort high、temperature 0，与 cmp_chat_noprobe_5 同。

## 4. 指标（`ident3_score.py` → IDENT3_REPORT.{md,json}）

1. 每题每臂：10 遍的成功数、步数分布、总生成 token 分布、task_error/abort 数。
2. 30 次同题跑两两配对：首个分叉步、该步内首个分叉 token 位；分**同臂对**
   （chat-chat / np-np / nf-nf）与**跨臂对**（chat-np / chat-nf / np-nf）报中位与
   "整题逐 token 全同"的对数。同臂对与跨臂对分布一样 = 臂间无差别可言。
3. prompt id 核对：chat 的 `prompt_token_ids` 与 noprobe/nofill 的 prefix 在分叉前
   的步逐位相等的比例（应为 1.0，不是就是管线问题）。
4. nofill 专属：开火次数、每次 `overflow_identical` 比例、`overflow_match_len` 分布、
   `dropped_chars` 分布、decode 核对全过。
5. 事实表，不带解读。

## 5. 裁决点

| # | 裁决 | 我的选择 | 备选 |
|---|---|---|---|
| E1 | 探针权重已删，nofill 臂怎么触发 | 伪规则：每步第 5 个句尾切口开火一次 | 第 1 个（几乎每步都开、但 head 极短）；随机切口（10 遍不可复现） |
| E2 | 切口落 token 边界 | head = 盖住句尾标点的最短 id 前缀（review 后改：只看 token 序列、与流分块无关；原稿"退到不晚于字符切口的块边界"在 stop 串压字符、多 token 并块时不准） | 退到不晚于字符切口的最近边界（把独立的空白 token 也带上，分块相关） |
| E3 | 重发核对 | decode 与流文本公共部分不等就抛错停跑；步末 decode(gen_ids) vs raw 只记不抛 | 静默退一个 token 再试 |
| E9 | 句尾切口计数 | 按 `m.start()`（review 后加：按 end 记时同一句尾随空白分块会算两次，"第 5 个"随分块变） | 按 `m.end()`（回放线口径） |
| E10 | 步预算 | `8192 − 留下的 id 数`（丢弃溢出不吃预算，chat 一步 8192 全是留下的） | `8192 − 全部生成 token`（nofill 早顶 length） |
| E11 | 发射前门禁 | `ident3_gate.py`：chat `prompt_token_ids` == `/render` 逐 id，不等整臂拒跑（钉 vLLM 日期与 return_token_ids） | 不查（vLLM 没钉日期时三臂各自跑完、报告看不出原因） |
| E12 | 打分排除 | 任一臂 abort 非空都不进成败与配对（chat 的 `stepN:Err`、live 的 `task_error:*`、撞顶、无 final） | 只排 `task_error:*`（chat 的失败跑会当短轨迹进配对） |
| E13 | prompt 核对 | 按 sha1 逐 id 比（chat 存整段 prompt_token_ids，live 存 prefix_sha） | 只比 token 数（日期不同长度也相同，查不出） |
| E4 | 三臂并行还是全串行 | 三臂并行、臂内串行（≈2.5h） | 全串行（≈6h；批组成噪声更少，但生产里本来就有批） |
| E5 | chat 臂改动 | 只加 `return_token_ids` 记录字段，不改行为 | 不动（就没法逐 token 比 chat） |
| E6 | 题目 | 沿用 cmp_chat_noprobe_5 的 5 题 | 换 5 题（与旧数据不接） |
| E7 | NOTE 前导换行（本批不跑，只改代码） | head 以空白结尾则不加 `\n`（D5'） | 一律 `\n` |
| E8 | 溢出比对 | 存被丢弃的 id，与重发后同位新 id 逐位比 | 不存（就只能看题级结果） |

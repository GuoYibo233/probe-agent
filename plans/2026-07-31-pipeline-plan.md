## 1. 十条共识（盘问拍板结果）

1. **代码新建一套，数据不重采。** 旧轨迹（`envs/runs/` 下全部批次）是冻结库存，
   原样喂给新流水线；新代码可以参考旧代码。
2. **口径全盘继承，一条不改**：切样本规则（调用前 ≥40 字符起可切、每事件最多 64 个
   切点、`Task/[HISTORY]/[THINKING]` 拼版式）、损失权重 `w = 1/m`（每事件总贡献为 1）、
   评测法（val 拟温度 + 扫门槛、test 冻结一次）。
   **新流水线的验收线 = 喂旧轨迹能复现 v3 的旧数字**，先证明管子不漏水再加新东西。
3. **全自动标注，失败轨迹照用。** 标签从轨迹里直接抄：只预测工具档 = 工具名，
   连参数档 = 完整调用。探针学"这个模型接下来会调用什么"，不是"应该调用什么"。
4. **探针矩阵四格齐跑**：因果（Qwen3-0.6B）/ 非因果（ModernBERT）× 只预测工具 /
   连参数。参数判分口径用现成的（`envs/bert/param_label.py` 的归一化 +
   `eval_extract.py` 的宽松/严格/整调用三档）。唯一要新写的零件：
   **因果侧生成参数的判分器**（生成文本 vs 真值比对，归一化规则照抄 param_label）。
5. **一次只跑一个任务，卡全堆给它。** 第一站 appworld；bfcl 第二站串行；
   再往后扩展（ALFWorld 已探明可低成本接入，见当日 subtask 报告，候选第三站）。
6. **appworld 用官方分区，不自己切**：
   train 区 90 题训练、dev 区 57 题当 val（选检查点 + 拟温度 + 扫门槛）、
   test_normal 区 168 题只考一次。test_challenge 区 417 题继续不碰。
   （bfcl 没有官方多分区，轮到它时自己切一次三堆即可。）
7. **采集清单（全场唯一要采的）**：qwen3.5 补 train 区 90 题欠账；
   三个模型各采 test_normal 区 168 题。合计 90 + 168×3 = 594 题-模型，
   按第一批中位 172 秒/题估约 28 GPU 小时，三路并行墙钟一晚上。
8. **三个模型并行做**，qwen3.5 / qwen3.6 / gpt-oss 各训各的探针
   （qwen3.5 与 qwen3.6 始终是两个模型，不合并）。同题同量，公平性天然成立。
9. **注入段留接口、不跑实验**：训练产物（检查点 + 温度 + 门槛）按
   `envs/loop/probe_server.py` 能直接加载的格式存盘。端到端实验等矩阵结果
   出来、知道哪格值得注入之后另行立项。
10. **采集是新流水线的第一段**，收编旧采集脚本（幂等、断点续采，参数不动），
    今晚的发射就是新流水线第一段的第一次运行。

## 2. 执行序（三波）

### 第 0 波：采集（今晚，长杆先行）

**并行原则（用户 2026-07-31 深夜追加）：尽量并行，多用卡缩墙钟。**
服务侧的天花板是 tokyo108 的 6 张大卡——27B 权重 54G、gpt-oss 63G，
A6000 的 48G 装不下，历史上所有 vLLM 实例都是 tokyo108 单卡一实例。
所以第 0 波拉满 = **6 卡 6 实例 + 客户端并发**：

1. commit 当前工作树（仓库铁律：发射前 HEAD 必须干净可追）。
2. 走 **gpu-run skill** 全生命周期发射，每模型双实例、题单对半分：
   - qwen3.5-27b ×2 实例：258 题（train 90 + test_normal 168）对半 129/129；
   - qwen3.6-27b ×2 实例：test_normal 168 题对半 84/84；
   - gpt-oss-120b ×2 实例：test_normal 168 题对半 84/84（吃显存大，优先 H200）。
   qwen3.5 是长杆（每实例 129 题），它的客户端并发开高一档拉平三路。
3. 采集脚本用旧的（`envs/collect/` 那套），断点续采；发射前照例现探空卡。
   墙钟估 3–5 小时（并发下的估计，以实测为准；纯单流串行才是 12 小时）。

### 第 1 波：写新流水线（采集跑着的同时，不占 GPU）

**逐段的工程细节与 GPU 请示计划在 `plans/2026-07-31-pipeline-engineering.md`**，
本节只留骨架。顶层新建 `pipeline/`（名字可改），五段：

| 段 | 内容 | 来源 |
|---|---|---|
| collect | 收编旧采集脚本 | 旧代码搬入 |
| annotate | 切样本 + 两档标签（工具名 / 完整调用） | 参考 `build_dataset.py` + `param_label.py` |
| train | 骨架 × 头，配置两个开关定四格 | 参考 `train_probe.py` / `train_causal_probe.py` / `train_extractor.py` |
| eval | val 选检查点 + 拟温度 + 扫门槛，test 冻结；官方分区单跑 | 参考 `eval_replay*.py` / `eval_extract.py` |
| inject | 只定产物存盘格式（probe_server 可加载），无实验 | 参考 `envs/loop/` |

**验收线**：喂 v3 bfcl 旧轨迹，复现旧数字后才准跑正式实验。写完不逐段试跑正式数据，
一把过验收（用户口径："先把代码都写出来，然后再去运行"）。

### 第 2 波：appworld 探针矩阵（料齐 + 管子验过之后）

1. 造数据集：3 模型 × 官方分区（train/dev/test_normal），两档标签一次做齐。
   **不并入 v3**，v3 一个字节不动。
2. **12 次训练**（4 格 × 3 模型），单次约 2 小时，走 gpu-run。
   训练池是 tokyo105/106/107 的 19 张 A6000/6000Ada，12 次一把全并行，
   墙钟 ≈ 单次的 2 小时——这是"多用卡缩墙钟"在第 2 波的兑现。
3. 评测：每个探针在 dev 上定温度和门槛，test_normal 冻结考一次，出全矩阵报告。
4. 记账：`record.py` start/finish、`runs.jsonl`、TIMELINE 补条目。

### 第 3 波（展望，不在本轮）

bfcl 三堆单切（数据已齐，零采集）→ 环境扩展（ALFWorld 候选）→ 注入端到端实验。

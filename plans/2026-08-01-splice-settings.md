# 2026-08-01 拼回设定讨论定稿（detail-check 落盘）

## 目标（已经用户确认）

给 gptoss × AppWorld 的回放注入实验定下"小模型预测怎么拼回大模型"的完整设定：
两种小模型（ctool 只报工具名 / cgen 写整条调用）各配"大模型验算 / 不验算"两种用法，
共四种设置；每种设置定清拼什么、怎么收口、猜错怎么算账、省 token 怎么算、落在哪。
明确不做：in-loop rollout（挂探针从头跑完整题拿任务级分数）、q35/q36 两个模型侧。

## 四种设置（主表，名字全场专用）

| 设置 | 小模型给什么 | 大模型验不验 | 大模型干什么 |
|---|---|---|---|
| 甲 | 工具名(ctool) | 验工具名 | 不同意就换自己的，然后写参数 |
| 乙 | 工具名(ctool) | 不验 | 顺着骨架直接写参数 |
| 丙 | 整条调用(cgen) | 逐token验名+参数 | 拒绝点起自己续写 |
| 丁 | 整条调用(cgen) | 不验 | 调用直接执行（=已跑完的 execute 档，旧曲线直接入表） |

关键结论（讨论中确认）：甲和丙在正确率轴上是同一个点（验完都收敛到大模型自己认可
的调用，greedy 下逐字同），差别全在算力轴（丙验收通过的 token 白拿）。真正拉开正确
率的是乙（工具名被 ctool 钉死）和丁（整条被 cgen 钉死）。四种设置四条独立臂分别执行。

## 行动清单

1. **骨架拼法四变体**（管甲乙的拼接）：裸骨架 / 候选A(`Thus code:`+围栏) /
   候选B(散文式) / 直接转场（照抄模型原生的思考→正文通道切换字节，即"塞停止思考
   标签"，结构上根治"接了茬还想"；光塞标签不塞工具名 = 大模型自写整条的对照臂，
   兼作甲丙正确率锚点）。
   直接转场臂拼的字节定稿：`<|end|><|start|>assistant<|channel|>final<|message|>`
   + ```` ```python ```` 围栏 + `print(工具名(`（print 包裹占原生 83.9%；login 类
   赋值形态 13.4% 按 label 分流不套 print）。
   **结果后停止标签开关（新增）**：思考段各臂把结果按 [SYSTEM NOTE] 塞回后，
   可紧跟同一串通道切换字节，逼模型立刻去正文段写正式调用。每臂跑开/关两档。
   定位说明：原轨迹实测收到工具结果后模型 100% 会继续思考（2041 步无一为零，
   中位 3142 字符，比首步 1873 还长），所以这个开关压制的是天性不是病——
   它量的是"掐掉结果后思考，调用质量掉多少、token 省多少"。
   决定性理由：话术必须从模型自己 1476 个原生引导句里逐字偷（SPORK format
   divergence + 塞入内容分布落差论文 + 本工程 hotpot RESULT 行复读事故，三证同源）。
   授权句(--permit)留消融臂、默认关。—— 主对话执行
2. **收口三件事**：截取完整调用认"右括号配平 + 围栏关闭"（原生 92% 的正文段
   以围栏收尾零废话；解析器须认得字符串内括号）；执行复用 exec_calls.py 重放执行；
   结果回填分两路——思考段臂用 [SYSTEM NOTE] 模板（可叠加结果后停止标签开关），
   直接转场臂走原轨迹式环境消息。甲乙的参数是大模型现写的自带引号，
   requote 启发式坑消失。—— 主对话执行
3. **触发判定可插拔**：默认沿用现行三步（val 拟温度→val 扫θ按风险档挑→test 冻结）；
   判定来源留接口：全局阈值 / 外部逐时刻判定文件。用户在训的产阈值模型
   训好后直接产判定文件接入，管线不改。丙丁可选 cgen 自触发
   （整条最弱 token 概率过阈值，val 673 事件上校准，一张卡个把小时）。—— 主对话执行
4. **验收对账脚本**（管甲丙）：cgen 草稿 vs 大模型自写，用 gpt-oss 分词器逐 token
   比最长公共前缀 = 接受长度，报告接受率（对标 SPORK 的 α）。备用精确路：
   completions 的 echo+logprobs 打分（vLLM 0.26.0 实装已验证支持，
   max_tokens=0 拿逐 token rank，rank≠1 即拒绝点）。两条都算、报不一致率
   （vLLM 批处理下 logprob 有抖动）。—— 主对话执行
5. **猜错分桶**：统一 execute 口径（写出来就真执行、结果原样塞回）。
   乙记"骨架工具名≠原轨迹工具名"桶，丁记"整条≠原轨迹"桶，
   甲丙只记拒绝率（拒绝是省不成，不是错误）。
   已知局限写明：标尺是原轨迹调用，甲丙的合理偏离会被算错，系统性低估。—— 主对话执行
6. **省 token 账**：主对照 = 原轨迹（模型当时从截断点到发出调用实际写的 token，
   盘上现成）；nofill 降级为管线体检线（nofill≈原轨迹才放行整批数字）。
   逐事件配对差值，报中位数+分布，不用总和（θ 曲线实测总和轴淹在噪声地板下）。
   丙另记"验收白拿 token 数"列。直接转场臂的终点口径须先钉死。—— 主对话执行
7. **落地位置**：replay_inject.py 加 skeleton 系列 arm；plan 段补存探针预测工具名
   （现在只存对错不存名字——忘补则骨架拼成真值、整条曲线变上帝视角，最高优先）；
   score 段加三列：骨架是否补完 / 工具名是否被改写 / 补完后又想了多少字符。—— 主对话执行

## 依据与来源（讨论中引用的外部证据，均由侦察 agent 抓原文核实）

- **验收机制的三层说法**：投机解码本身（草稿-验收，greedy 下输出与大模型独立生成
  逐字相同）；SPORK（arXiv 2607.03333）的 forced-prefix probe——强拼调用开头提前
  写完整调用、与正式生成比对报接受率 α，与我们的 delta = 它大模型自分叉起草、
  我们 0.6B 起草；PASTE（arXiv 2603.18897）的逐字匹配放行 = 丙的接受判据先例。
  注意：验收查的是"大模型也会这么写"，不是"写得对"——错误率对齐到大模型水平为止。
- **话术必须偷原生句**的三证：SPORK format divergence（格式不合→α 塌到 4.5%）、
  arXiv 2512.02389（塞入内容与模型分布落差→自纠能力失效）、本工程 hotpot
  RESULT 行不逐字回显→无限复读事故（hotpot_inject/FINDINGS.md:36）。
- **vLLM 侧工程事实**（实装 0.26.0 源码级核实）：completions 的 echo+logprobs+
  max_tokens=0 纯打分模式可用，prompt_logprobs 带 rank 字段；prediction 参数
  两次 closed as not planned（issue #12061/#10137）；gpt-oss 挂 eagle3 有质量崩塌
  前科（issue #27626，MMLU 0.73→0.28）；批处理下 logprob 不保证逐位稳定。
- **骨架左括号的 token 切分陷阱**：arXiv 2601.23223（partial token problem，
  代码域重灾）——上线前用 gpt-oss 分词器实测 `login(` 的切法，必要时骨架砍到括号前。
- **拼骨架必须用探针预测值而非真值**：plan 段现在只存对错不存预测名
  （replay_inject.py:169），忘补则整条曲线变上帝视角。

## 讨论中砍掉/改掉的东西（防止回潮）

- 五档编号（档1–档5）作废，改用甲乙丙丁 2×2：档1=乙、档2/3=丁、档4=丙、档5 并入甲。
- "两档触发共用 ctool"曾锁又被推翻：cgen 无现成扳机（生成模型无单一分数），
  但可用最弱 token 概率造一个；最终定为触发源可插拔。
- nofill 当省 token 主对照：撤销，改原轨迹为主对照、nofill 转体检。
- SYSTEM NOTE 现役注入的实测病：模型吃注入（重调率 0.80→0.33）但多想 264 字符，
  省 token −129——"接了茬还要重新盘一遍"，这是骨架/转场方案的动机。

## 方向笔记的规矩

用户口头提的意见先落**当天那份** `<日期>-direction-notes.md`，一条意见一节，
写清意见原话、当时在讨论什么、改了哪个文件、还欠什么。**一天一份，不覆盖不合并**，
第二天开新的，旧的移进 `archive/`。

这里是过渡层不是终点：确认要长期生效的条目，往 `TIMELINE.md`（方向决策）
或 `DATA.md`（数据设定）搬定稿，搬完在原条目下注明搬到哪了。

## 状态书的更新规矩

同一条线第二次出状态书走**更新模式**：新写一份完整的（`exp-status` skill 的产物必须自洽），
旧的那份当天移进 `archive/`，不要两份现役状态书并存——并存就会出现同一个数字两种说法。

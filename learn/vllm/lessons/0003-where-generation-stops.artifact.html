Lesson 0003 · vLLM 0.26.0

它停在哪个字上，由两套机制决定

一套在 token 层，一套在文本层。两套的触发条件不一样，而文本层那套会被另一个旗标悄悄关掉。我们采集线上就有一个这样的停止串，它从来没生效过。

两套机制，分开记

右边那一栏最后一行是这一课的全部。下面拆开看。

停止字符串比的是「解码后的文本」

比的是 self.output_text——一个逐 token 累积起来的字符串。那么这个字符串是怎么攒出来的：

解码流是带着 skip_special_tokens 建的。这个值默认是 True——两处都写着，引擎侧 sampling_params.py:295，HTTP 接口侧 entrypoints/openai/completion/protocol.py:82。

推论：默认设置下，特殊标记根本不会进入 output_text。所以一个由特殊标记组成的停止字符串——<|im_end|>、<|return|> 这种——永远匹配不上。它不会报错，只是一句空话。要让它有效，得同时给 skip_special_tokens=False。

我们两条线，一条给了一条没给

注入线：给了 pipeline/inject/replay_inject.py

这条给全了，停止串能匹配上。顺带一提，<|return|> 正好也是 gpt-oss 的 EOS（tokenizer_config.json 里 eos_token 就是它，id 200002），所以这里两套机制同时在管。

采集线 raw 模式：没给 envs/collect/common.py

没有 skip_special_tokens=False，所以按上面那条推论，这个停止串在服务端是空转的。

那为什么采集没出事？因为还有另一套机制在兜底：引擎会把模型的 EOS token id 自动加进停止 token 集合。

一处我核不了的地方。上面这条兜底成立的前提是 <|im_end|> 就是那批 Qwen 模型的 EOS。那批权重已经不在 /net/…/models/ 了（现在只剩 gpt-oss-120b 和 Qwen3-0.6B-Base，后者的 eos_token 是 <|endoftext|>）。所以我只能说"停止串是空转的"，不能替你断定"生成一定停在了正确的地方"。下次起 Qwen 服务时自己验一句，方法写在最后一节。

停止串到底进不进输出

默认不进。命中停止串时，output_text 会被截到停止串之前（detokenizer.py:138–140）。所以你拿到的文本里看不到那个串——不是模型没写，是服务端剪掉了。

finish_reason 只有五个值

值含义我们在哪儿用它
stop撞上停止 token 或停止串正常收尾
lengthmax_tokens 用完，或撞上下文上限replay_inject.py:1050 数截断条数
abort客户端中止（第 5 课讲）活跑驱动打断重发时
error / repetition引擎报错 / 触发复读检测目前没处理

stop 这个值本身不告诉你是撞了哪一个。要知道是哪个，看响应里的 stop_reason——命中停止串时它是那个串，命中停止 token 时它是那个 id（outputs.py:46–47）。

练一练

不许翻上面。答错立刻有反馈，答完就锁。

1. stop 里的字符串，是拿去跟什么比对的？

对。detokenizer.py:131-137 传进去的是 self.output_text，一个字符串。

那是 stop_token_ids 的活。stop 比的是解码后的文本（detokenizer.py:131-137）。

不是。只比生成出来的部分，提示词不参与（detokenizer.py:131-137）。

2. 默认设置下，把 <|im_end|> 当停止串会怎样？

对。skip_special_tokens 默认 True，特殊标记不会进 output_text，所以匹配不到。不报错，就是空转。

不会。解码流是带 skip_special_tokens=True 建的（detokenizer.py:184-187），那个串压根不出现在被比对的文本里。

不报错。这正是它麻烦的地方——它安安静静地什么都不做。

3. 想让特殊标记当停止串真的生效，要额外给什么？

对。注入线就是这么写的（replay_inject.py:814）。给了它，特殊标记才进被比对的文本。

那个只管"命中后要不要把串留在输出里"，不管匹不匹配得上。

这是绕开文本层、改走 token 层——也能停住，但不是让 stop 生效的办法。

4. 命中停止串后，返回的文本里含不含那个串？

对。include_stop_str_in_output 默认 False（sampling_params.py:299），文本被截到串之前。

默认不含。要含得显式给 include_stop_str_in_output=true。

跟长度无关。是 include_stop_str_in_output 这一个开关说了算，默认 False。

5. finish_reason == "length" 意味着什么？

对。max_tokens 用完或撞上下文上限。replay_inject.py:1050 就是靠它数截断条数的。

那是 "stop"。"length" 是额度打满，内容多半是被切断的。

那是 "abort"。"length" 跟连接无关，是额度用完了。

下次改停止条件之前做这三件事

  1. 问一句：我的停止串里有没有尖括号包起来的特殊标记？有，就必须一起给 skip_special_tokens=false，否则它是空转的。
  2. 验一句模型的 EOS 到底是哪个，别靠印象： 
    python3 -c "import json;print(json.load(open('<权重目录>/tokenizer_config.json'))['eos_token'])"
    兜底靠的就是它。EOS 对不上，停止串又是空转，那才真的会写到 max_tokens 为止。
  3. 产出里把 finish_reason 存下来。它是事后判断"这条是正常收尾还是被截断"的唯一依据，事后补不回来。

先读这一份：vLLM SamplingParams——只看 stop、stop_token_ids、skip_special_tokens、include_stop_str_in_output 四条。⚠️ 默认值以本机 envs/vllm-env/…/vllm/sampling_params.py 为准。

## Background

The new trainer drops whole events whose full-text token count exceeds `--max-len` (8192) (`share_data.load_events`); the ctool trainer does the same (`train_causal_tool.load_events` returns `(events, dropped)`). The eval side currently left-truncates: cgen / cparam's `generate()` left-truncates the prompt to `max_len - max_new` (`eval_causal_call.py` lines 213-214, `eval_causal_param.py` lines 208-209, `tok.truncation_side = "left"` at lines 590 / 420), and ctool's `score_causal` (`eval_tool.py` lines 116-160) left-truncates the full text to `max_len`, recording zero logits and counting `n_oow` for cut points outside the window. gyb wants all three treatments turned into switches for later comparison.

## What to do

1. `share_data.py`: pull the full-text tokenization at `load_events` lines 146-147 out into a module-level function `full_token_ids(tok, full_text) -> list[int]` (keeping `add_special_tokens=False, truncation=False` as-is), then define `n_full_tokens(tok, full_text) -> int` right after it, its body being `return len(full_token_ids(tok, full_text))`. Change the loop at `load_events` lines 145-153 to `full_ids = full_token_ids(tok, e["full_text"])`, then keep judging `len(full_ids) > max_len` and writing `e["full_ids"] = full_ids` and `e["n_full"] = len(full_ids)` as before (tokenization count unchanged; an event is still tokenized only once). Change `train_causal_tool.load_events` line 128 to `n_full = share_data.n_full_tokens(tok, e["full"])` (it only needs the count; it never had `truncation=False`, but no truncation was already the default, so the value doesn't change). Also put two more pure functions used only by the eval side into `share_data.py`: `event_full_texts(rows) -> dict[event, full_text]` (the text of the row with the largest `sent_idx`; do not touch the grouping in `load_events`'s `events_all.append(dict(...))` block -- that block's exact order is pinned by spec 3.2's random-number consumption order) and `select_keys(mode, keys, n_full, prompt_len, excluded_rows, max_len, max_new) -> (kept_keys, counts)` (`n_full` and `prompt_len` are dicts keyed by key, `excluded_rows` is the set of excluded rows passed in from ctool, `counts` is a dict of the four integers `n_left_truncated / n_skipped_rows / n_dropped_events / n_excluded_by_ctool`); both cgen and cparam call this one function (both scripts already put `pipeline/train` on `sys.path`; writing one copy each would be two sources of truth).
2. Add `--overlong` to `eval_causal_call.py` and `eval_causal_param.py`, `choices=["left", "skip", "drop-event"]`, default `left`. Implement the three modes exactly per spec 16.2's criteria:
   - Prompt length `L(k)`: for cgen, `len(tok(fired[k]["row"]["text"] + sep, add_special_tokens=False, truncation=False)["input_ids"])` (matching `generate()`'s tokenization at line 213); cparam builds two prompt sets for the same batch of `keys` (lines 432-433, `for tag, given in (("gt_tool", gt_given), ("pred_tool", pred_given))`, both blocks sharing the same `keys` -- the comment at lines 403-404, `n = len(keys)` at line 440, the top-level `n_events_scored` at line 446); `L(k)` takes the max token count across both prompt sets, and all three modes use only this one `L(k)`, so both blocks' denominators remain the same batch of `keys`.
   - Three steps in a fixed order: readonly exclusion (lines 576-580) -> `--overlong` filtering (after the tokenizer loads, calling `select_keys`) -> `--limit` (lines 581-582); for cparam, the filtering goes right after `pred_given` is built at line 429 and before the loop at line 432, changing only the `keys` list. `n_events_fired` keeps its pre-filter meaning.
   - `left`: unchanged behavior, just add the count `n_left_truncated` (the number of rows where `L(k)` exceeds `max_len - max_new`).
   - `skip`: rows where `L(k)` exceeds `max_len - max_new` do not enter `prompts`, do not enter `keys` (hence do not enter the overall table, the per-tool buckets, or the samples), counted as `n_skipped_rows`.
   - `drop-event`: for every event in `keys`, take its full text by `share_data`'s grouping rule (`share_data.py` lines 121-131: no row filtering, the text of the row with the largest `sent_idx`); drop the whole event from `keys` if `n_full_tokens` exceeds `meta["max_len"]`, counted as `n_dropped_events`; among the rows left, ones whose prompt is still overlong get left-truncated and counted as `n_left_truncated`. Only tokenize the events in `keys` (the test set has 391,893 rows; do not tokenize the whole set).
   - The interface with the ctool eval (spec 16.2's "interface" paragraph): both scripts' `assert len(rows) == logits.shape[0]` at lines 569 / 397, which aligns with `logits_test.pt` by position, stays as-is. cgen / cparam compute their own firing points from the logits and theta (lines 495-497 only read `temperature` and `chosen_theta` from REPLAY_REPORT), so after reading `excluded_idx` from `logits_test.meta.json` (written by item 3 below; treat a missing key -- an old cache -- as an empty list), those rows must not be candidates for a firing point (zero logits through softmax give a uniform distribution, so theta alone can't block them); pick the firing point among the remaining rows of an event; an event whose candidate rows are all excluded has no firing point and is not scored, counted as `n_excluded_by_ctool` (counting events). ctool's `skip` only excludes out-of-window boundaries, and rows inside the window for the same event can still fire as usual; this rule maps ctool's "exclude boundaries" straight onto this side's "exclude candidates."
   - Reports: both the JSON and MD write `overlong_mode` and the four counts `n_left_truncated / n_skipped_rows / n_dropped_events / n_excluded_by_ctool` (write 0 for ones that didn't happen, never omit the key); cparam additionally writes the diagnostic key `n_left_truncated_by_tag = {"gt_tool": n, "pred_tool": n}` (each counted against its own prompt-set length; cgen does not write this). None of the existing keys read by the ACCEPT scripts are renamed. The `--self-fire` path (line 378, `self_fire_block`, which calls `generate()` separately) is untouched; the report's `overlong_mode` only describes the main path.
3. Add `--overlong` (same three values, default `left`) to `eval_tool.py`'s `score_causal` and the main flow that calls it:
   - `left`: unchanged.
   - `skip`: out-of-window boundaries (the ones where `read_position` returns -1) do not enter any denominator and produce no firing point; counted as `n_skipped_bounds`.
   - `drop-event`: events with `n_full_tokens(tok, full text) > max_len` are excluded whole (all their boundaries), counted as `n_dropped_events`, `n_dropped_bounds`. "Full text" here follows ctool's own trainer's rule (`train_causal_tool.py` lines 93-96: filter rows by `label in label2id` first, then take the last row's `text`) -- `eval_tool.py`'s `rows` is already the filtered set, and `full` at `score_causal` line 124 is exactly this; do not switch this to share_data's unfiltered rule (spec 16.10 #34 records the difference between the two).
   - Shape unchanged: `logits_*.pt` writes the full row count under all three modes, with excluded rows getting zero logits (same as the current handling of `n_oow`); `score_causal` returns `(out, excluded_idx)`, `excluded_idx` being the list of excluded row indices (empty under `left`). The caller writes `excluded_idx` into `logits_*.meta.json` (adding `overlong_mode` and `excluded_idx` alongside the existing `weights / rows / adopted` keys); excluded rows are dropped before computing metrics and REPLAY_REPORT. Downstream, cgen / cparam align with `logits_test.pt` by index (the hard assertion at `eval_causal_call.py` line 569), so the row count must not change.
   - `--cached-logits` path (around `eval_tool.py` line 404): `SystemExit` with a message naming both modes if the `.meta.json`'s `overlong_mode` differs from this run's `--overlong` (or the key is missing and this run isn't `left`); otherwise proceed as usual and read `excluded_idx` back from `.meta.json`.
   - `REPLAY_REPORT.json/.md` writes `overlong_mode` and the three counts, and also writes `n_oow` into it (currently just a print at `score_causal` line 158, not in the report).
   - `--overlong` only takes effect for `--head causal`: `max_len` and `tok` are only assigned in the causal branch (lines 353-360); passing anything other than `left` with `--head mbert` is an immediate `SystemExit` with an explanation; mbert's report always writes `overlong_mode` as `left`, with all three counts 0.
4. Test `tests/test_eval_overlong.py` (spec 16.9, first item): skip if the real tokenizer path `MODELS["qwen"]` doesn't exist. Build 3 events by hand (one with a full text over a very small `max_len`, one whose prompt just barely exceeds `max_len - max_new`, one normal), and assert: (a) `n_full_tokens` on the same text agrees with `load_events`'s `dropped_events` criterion; (b) `share_data.select_keys`'s counts and the surviving key set under all three modes, plus exclusion given `excluded_rows` (an event with some but not all candidate rows excluded stays; one with every candidate row excluded is dropped and counted into `n_excluded_by_ctool`); add a cparam case: one key whose ground-truth tool name and predicted tool name differ in token count, where only the `pred_tool` prompt exceeds `max_len - max_new`, asserting this key is excluded under `skip` (the max-of-two rule), `n_skipped_rows == 1`, and under `left`, `n_left_truncated == 1` with `n_left_truncated_by_tag == {"gt_tool": 0, "pred_tool": 1}`; (c) under all three modes, `score_causal`'s returned `out` has the same row count as the input, `excluded_idx` and the counts each match, and excluded rows' logits are all zero (a small model can be a randomly initialized 2-layer `Qwen3Config` backbone with a linear head, following `tests/test_share_trainer.py`'s approach); (d) `--cached-logits` mode validation: hand-write a `.meta.json` with `overlong_mode: "skip"`, and reading it with `left` must `SystemExit`; (e) `--head mbert` with `--overlong skip` must `SystemExit`.

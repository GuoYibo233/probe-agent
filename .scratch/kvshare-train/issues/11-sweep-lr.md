## Background

gyb has ruled that the learning rate must be swept. Scale (decision 27): four base-model configurations x three learning rates = 12 runs, cgen cell, 1 epoch, `--eval-per-epoch 4`, selected by lowest `val_ce`. Launching goes through gpu-run (the main session); this ticket only does the two CPU tasks of "producing the list" and "collecting the report."

## What to do

1. `pipeline/train/sweep_lr.py`, with `argparse` and two subcommands:
   - `plan [--grid <json>] [--data <dir>] [--out-root <dir>] [--py <python>] [--track kvshare-lr-sweep] [--write <plan.json>]`. The `GRID` constant (a list, each item `dict(tag, base, lora: bool, lrs: list, tok_budget: int, card: str, extra: list)`) starts as (spec 16.6 decision 29, and 16.8 decision 30): `b06` (`qwen`, full-parameter, `[1e-5, 5e-5, 2e-4]`, 16384, "Ada", `["--grad-ckpt"]`), `b17` (`qwen17`, full-parameter, same, 16384, "H200", `[]`), `l17` (`qwen17`, LoRA, `[1e-4, 5e-4, 2e-3]`, 16384, "H200", `[]`), `l4` (`qwen4`, LoRA, same, 16384, "H100", `["--grad-ckpt"]`). The main session may change the constants again after smoke-testing, so write it in an easily-editable shape. run_id = `ks828<tag>_gptoss_cgen_lr<lr>`, `<lr>` obtained via `f"{lr:.0e}"` with the leading exponent zero stripped (`1e-05` -> `1e-5`, `2e-04` -> `2e-4`). Output directory `<out_root>/<run_id>`, `--out-root` defaulting to `pipeline/runs/sweep` (a repo-root-relative path; `plan`'s output writes it as an absolute path), `--data` defaulting to `pipeline/data/nyapass_aw_v1/gptoss`, `--py` defaulting to `<repo root>/cprobe-env/bin/python` (repo root taken via `Path(__file__).resolve().parents[2]`). Each command = `<py> <repo root>/pipeline/train/train_causal_share.py --mode cgen --base <base> --env appworld --data <absolute data path> --out <absolute out path> --lr <lr> --tok-budget <tb> --epochs 1 --eval-per-epoch 4 --log-every 10 --mem-probe` plus `--lora` (when `lora` is true) plus `extra` (`--log-every 10` must be written: at the default of 50, a one-epoch run with 516 updates would only print 10 step lines). After generating the list, self-check that no two run_ids match; if any do, `SystemExit` printing the colliding pair (including the raw lr value: `f"{lr:.0e}"` keeps only one significant digit, so a grid change to `1.2e-5` would collide). Output: print a Markdown table to stdout first (`run_id | tag | base | lora | lr | tok_budget | card | extra`), then a line reminding to replace the `--piece` placeholder with the actual card from the placement table, then 12 lines of `python3 run.py launch --cmd '<cmd>' --run-id <run_id> --track <track> --outdir <out> --piece <host>:<gpu>` (`shlex.quote` the whole command; `--piece` is required by `launch`, and `ops/launch_cmd.py` line 136 exits immediately without it, so the placeholder is printed as-is); if `--write` is given, also write the list as a JSON array (each entry `run_id, tag, base, lora, lr, tok_budget, card, cmd, outdir`). A `--grid` JSON file, if given, replaces `GRID` wholesale (same shape as the constant).
   - `report --runs <path or glob, nargs="+"> --out <dir>`: for each run directory, read `train_log.jsonl`: the `start` event gives `base, lora (whether the key is present), lr, tok_budget, n_train_events, dropped_events_train`; every `eval` event gives `frac, val_ce, val_exact_call` (or `val_exact_params`; write `null` if the key is absent); `done` gives `best_val_ce, best_frac, wall_s`; the max `peak_mem_gb` across `step` events; `mem_probe_summary`'s `worst_gb` (`null` if absent; for compatibility with runs whose probe only produced `mem_probe` events, take the max `peak_mem_gb` across those). The grouping key is `(base, lora)`, sorted by lr ascending within a group. Write `<out>/SWEEP_REPORT.json` (a list, each entry with all the above fields plus `run_id, status`) and `<out>/SWEEP_REPORT.md` (one table: `run_id | lr | val_ce@<ep>.<frac>... (these columns are generated dynamically, sorted ascending, from whatever `(ep, frac)` combinations appear across all runs' logs -- do not hardcode four columns) | best_val_ce | best_frac | val_exact(best) | peak_mem_gb | worst_gb | wall_s | status`; `status` is `done` or `running`, with a running row's best columns showing the lowest eval so far; each group's row with the lowest `best_val_ce` gets a `*` prefix on its run_id). One line before the table states when it was generated and how many directories were read; write no concluding sentence after the table. Directories missing `train_log.jsonl` print one warning line and are skipped, not an error.
2. `run.py`'s `TASKS` gains `"sweep-lr"`: `desc="learning-rate sweep list (plan) and report collection (report); launching still goes through gpu-run"`, `stage="train"`, `py="cprobe"`, `script` pointing at the new file, `notes` giving the two subcommands' usage and where the `GRID` constant lives. The field set follows the existing CPU entries (line 195's `gen-toolhop-splits` is the precedent: `stage / py / script / desc / notes`), no `gpu` key (only GPU tasks write `gpu=True`); `cmd_list / cmd_show` index `desc` and `stage` directly, so a missing one is a `KeyError`.

Test `tests/test_sweep_lr.py` (pure CPU, no torch needed): (a) `plan` with the default `GRID` produces 12 entries, run_ids pairwise distinct, each entry's `cmd` contains `--lr <that value>` and `--log-every 10`, entries with `lora` true contain `--lora` and those with it false don't, `--out` ends with the run_id; lr formatting `1e-05 -> 1e-5`, `2e-04 -> 2e-4`, `5e-05 -> 5e-5`; (b) `report` hand-builds two run directories in `tempfile` (one with `start` + 4 `eval` events + `done` + two `step` events + `mem_probe_summary`, one with only `start` + 1 `eval`), and produces a table: 2 JSON entries, `status` correct for each, `*` marking the row with the lowest `best_val_ce`, the row missing `done` has `status == "running"`, the number of `val_ce@` columns equals the number of `(ep, frac)` combinations that appear across the two directories; (c) `plan` given a `--grid` with a duplicate lr (`1e-5` and `1.2e-5`) exits with `SystemExit`.

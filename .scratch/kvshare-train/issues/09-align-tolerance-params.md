## Background

Round one's five thresholds (row 2e-5, per-token 3e-4, bf16 mean 2e-2 / max 1e-1, baseline factor 3x) are self-chosen values loosened based on measurement (decision 18); ctool's `--align-tol` was loosened from 1e-4 to 3e-4 (decision 20); gyb hasn't ruled on these. gyb wants them turned into parameters, plus a relative criterion as an alternative, to compare later against the numbers in `ALIGN_CHECK.json`.

## What to do

1. `train_causal_share.py`:
   - Delete the module-top constants `TOK_DIFF_TOL / BF16_MEAN_TOL / BF16_MAX_TOL` (lines 78-81), replacing them with parameters `--align-tok-tol 3e-4`, `--align-bf16-mean-tol 2e-2`, `--align-bf16-max-tol 1e-1`, `--align-baseline-factor 3.0` (the multiplier used for the baseline warning, currently hardcoded as `3 x`); `--align-tol 2e-5` already exists. `REF_INST_CE_DRIFT_TOL` is untouched (that's the reference path's own self-check, not a threshold). `run_align_check` reads from `args`, keeping no second copy of the defaults.
   - Add `--align-rule` (`choices=["abs", "rel", "both"]`, default `abs`) and `--align-rel-tol` (float, default 1e-5), placed after `--align-events` and before `lora_util.add_args(ap)` (tickets 08 and 10 also add parameters in the parameter section, at different anchor points; this ticket adds one key, `align_rule`, to `start_kw`, right after `align_bf16_warn`; the main session resolves merge conflicts at closeout). Judging: `abs` = current behavior (row-wise <= `align_tol` and per-token <= `align_tok_tol`); `rel` = `rel_max_abs_diff <= align_rel_tol`, where `rel_max_abs_diff = max_abs_diff / ref_scale`, `ref_scale = mean(|ce_ref|)` (the mean absolute value of the reference path's per-row ce -- using one divisor for the whole batch rather than each row dividing by its own ce, because rows with ce near 0 make the row-wise relative difference blow up; when `ref_scale == 0`, `rel_max_abs_diff` is written as `null` and the `rel` rule judges failure, printing the reason); `both` = both hold simultaneously.
   - `ALIGN_CHECK.json` always writes all of `rule, tol, tok_tol, rel_tol, ref_scale, rel_max_abs_diff, bf16_mean_tol, bf16_max_tol, baseline_factor` regardless of which rule is active; none of the existing keys (`PASS, n_events, ..., baseline_warn`) change.
   - Still `sys.exit(2)` on failure, with the failure message stating which rule was used and the corresponding numbers.
2. `train_causal_tool.py`: add `--align-rule` (same three values, default `abs`) and `--align-rel-tol` (default 1e-5). The relative quantities are already computed, so don't give them new names: `align_check` lines 243-250's `absmax_hidden`, `reldiff_hidden = d_h / max(absmax_hidden, 1e-9)`, `absmax_logits`, `reldiff_logits` (comment currently says "diagnostic only, not used for judging"). Judging: `abs` = current behavior, `max(d_h, d_l) < tol` (line 241); `rel` = `reldiff_hidden <= align_rel_tol` and `reldiff_logits <= align_rel_tol`; `both` = both hold. `ALIGN_CHECK.json` gains only two keys, `rule, rel_tol` (the relative quantities were already there). Change that "not used for judging" comment to explain that the `rel` rule uses them.

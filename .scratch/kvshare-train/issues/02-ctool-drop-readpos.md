## What to do

Change `pipeline/train/train_causal_tool.py` and `pipeline/eval/eval_tool.py`:

1. Drop rule (spec 11.1): `load_events` currently has no tokenizer; give it `tok` and `max_len` parameters, and after grouping, compute `len(tok(full, add_special_tokens=False)["input_ids"])` for each event; drop it and count it if it exceeds the limit, and add a count to the return value. Both calls in `main()` (train / val) must pass these; the `start` event gains `dropped_events_train, dropped_events_val`. Change `truncation=True` to `truncation=False` in `collate` (lines 137-138) and `align_check` (lines 209-210). Keep the `n_bound_dropped` field; keep writing it in the `step` and `eval` events as before, but change the comment to "the number of cut points where a read position could not be found, expected to be 0."
2. Default values (spec 11.2): `--max-len` 8192, `--accum` 2, `--bs` 4 unchanged, `--epochs` 3 unchanged. Sync the docstring and argparse help.
3. Read-position rule (spec 11.3): in both `collate` (lines 140-158) and `eval_tool.py`'s `score_causal` (lines 128-153), call `share_data.read_position(offsets, full, cut, keep)`, keeping `keep = int(enc["attention_mask"][i].sum())` (`train_causal_tool.py` line 143, `eval_tool.py` line 142) and passing it as the fourth argument. Delete only the body of the old `for t in range(keep-1, -1, -1): if 0 < ends[t] <= b` loop; keep the `if j < 0` guard in both places as-is (training side `dropped += 1`, eval side the `n_oow` count at lines 128, 150-152 unchanged). `align_check` (lines 201-243) has no cut-point loop; only change the `truncation` at line 209. `import share_data` in `eval_tool.py` can live at module top level (`share_data`'s top level does not import the training scripts, per spec 3.3), but follow the same `sys.path` style as lines 43-44.
4. Logging (spec 11.4): add `lr` (`sch.get_last_lr()[0]`) to the `step` event; change `loss` to the mean of all mini-batch losses since the previous step log, resetting the accumulator once the log is written.
5. Tests `tests/test_ctool_readpos.py`: (a) verify with hand-built offsets and full text that `collate` reads out the correct token index under the new rule (you may test `read_position` directly, then test `collate` on one real event with the real tokenizer); (b) `load_events`'s drop count: build two events, one with a full-text token count > max_len, and assert the returned event count and the drop count; (c) for an event within the limit, `eval_tool.score_causal` and `train_causal_tool.collate` read the same token index for the same cut points on the same full text (events over the limit are dropped on the training side and left-truncated on the eval side, so those don't apply here); (d) `eval_tool.score_causal` on a left-truncated event: a cut point outside the window is counted into `n_oow` rather than landing in cols.

# 08 Add generation-based evaluation back to the new trainer: `--gen-eval N` (default 200) and `--gen-bs`

Status: resolved
Blocked by: (none)
Spec: `.scratch/kvshare-train/spec.md` 16.3 (approach), 16.9 (tests), 16.10 #29 #30. Changes only in `pipeline/train/train_causal_share.py`, `pipeline/train/share_data.py` (row tuple gains a 6th slot), `tests/test_share_trainer.py`, `tests/test_share_data.py` (hand-built row tuples gain the 6th slot). Do not change the old scripts, do not change `run.py`, do not change docs.

## Background

The old trainer sampled 200 rows with a fixed seed at every evaluation and did greedy generation, reporting `val_exact_call` (cgen, `train_causal_callgen.py` lines 309-331 `eval_gen`, lines 448-450 sampling, lines 535-538 logging) or `val_exact_params` (cparam, `train_causal_param.py` lines 235-259, 358-360, 418-422), feeding only the log and never selecting best. The new trainer dropped this in round one per decision 4. gyb wants it back as a switch, recommended on (200).

## What to do

1. `share_data.load_events`'s row tuple (line 205) gains a 6th slot, `dict(tgt=<target string>, tool=<tool name or None>)`, fixed per mode: for cgen, `gen=dict(tgt=r["label_call"], tool=None)` (the cgen branch has no `tgt_str` variable; lines 179-183 tokenize `r["label_call"]` plus eos directly); for cparam, `gen=dict(tgt=tgt_str, tool=r["label"])`. `tgt` is the raw string without eos; `eval_gen` compares against it whole. Slots 0-5 are untouched. `pack_event` at line 274 unpacks six names, `_sent_idx, _text, p, seg_ids, seg_lab, _w = row`, which would raise `ValueError` on a 7-tuple -- change to `_sent_idx, _text, p, seg_ids, seg_lab, _w = row[:6]`. Other places that read the row by index (`share_data.py` lines 214-215, `train_causal_share.py` lines 179 / 470 / 789) need no change. Every place in the tests that hand-builds a 6-slot row tuple must gain the 6th slot: `tests/test_share_trainer.py` around lines 374 / 437 / 495, and the equivalent constructions in `tests/test_share_data.py`.
2. Add `--gen-eval` (int, default 200, 0 disables), `--gen-bs` (int, default 8), and `--gen-eval-at` (`choices=["all", "last"]`, default `last`: only generate at the evaluation point where `frac == E`; `all` generates at every evaluation point) to `train_causal_share.py`, all three right after `--log-every` (tickets 09 and 10 also add parameters in the same section, each at their own anchor point; this ticket adds two keys, `gen_eval / gen_bs`, to the `start_kw` dict, right after the `log_every` key; the main session resolves merge conflicts at closeout).
3. Sampling (per spec 16.3): once `ev_events` finishes loading, flatten it into a row list (events in load order, rows in within-event order) without filtering (share_data's rows all have targets; the old trainer's `callgen` filter at line 448 on `r[5]` is "has an LM target or not," a boolean, not a weight, and there's nothing corresponding to it here), then `random.Random(SEED).shuffle` and take the first N. Store as the tuple shape each mode needs: cgen `(text, None, None, tgt)`, cparam `(text, None, None, tool, tgt)`.
4. Generation: call `train_causal_callgen.eval_gen(model, tok, rows, dev, amp, args.max_len, args.gen_bs)` or `train_causal_param.eval_gen(...)` (per `args.mode`), do not write a new generation function; both old functions handle `padding_side / use_cache / model.eval() / model.train()` themselves. Call site: after `eval_ce` and before writing the `eval` event at each evaluation point; time it as `gen_s`. Generation must happen outside `_attn_ctx` -- `_attn_ctx` currently only wraps `_forward_packed`, keep it that way; don't wrap the whole evaluation block in it just for convenience (spec 16.10 #29: `generate` without a mask goes through GQA, and the mem-efficient kernel raises `No available kernel`).
5. Logging: add `val_exact_call` (cgen) or `val_exact_params` (cparam), `gen_n` (rows actually generated), and `gen_s` (seconds, 2 decimal places) to the `eval` event; when `--gen-eval 0`, and at any evaluation point under `--gen-eval-at last` that isn't the epoch's last, none of these three keys are written. The `start` event gains `gen_eval`, `gen_bs`, `gen_eval_at`. `save_best` still judges only on `val_ce`. `train_s` doesn't include generation time (the existing training clock only covers updates; confirm this stays that way).
6. Heartbeats during evaluation (spec 16.3, second-to-last item): `eval_ce(model, events, tok_budget, dev, amp, beat=None)` gains an optional `beat` parameter (callable with no arguments), called once every 25 physical blocks inside the block loop; the main flow passes `beat=lambda: heartbeat.emit(gstep, steps, "step")`, and calls `heartbeat.emit(gstep, steps, "step")` once before and once after calling `eval_gen` (don't pass anything else to `heartbeat.emit` -- its signature is `emit(done, total, unit, *, tok_in=None, tok_out=None, loss=None, status=None, stream=None)`). Reason: full val has 115,211 rows, plus 200 rows of generation; this window currently has no heartbeat at all, and the sampler's stall line at 5x the typical heartbeat interval (`ops/verdicts.py` line 14) would misfire.
7. Tests (spec 16.9, second item), in a new file `tests/test_share_gen_eval.py` (not appended to `test_share_trainer.py` -- tickets 09 and 10 run in parallel, and three tickets appending to the same file's end would collide; import the helper functions already in `test_share_trainer.py` for the small-model setup): (a) `--gen-eval 3 --gen-bs 2 --gen-eval-at all --eval-per-epoch 2` runs to completion, and every `eval` event has `val_exact_call` (or cparam's `val_exact_params`), `gen_n == 3`, `gen_s`; with `--gen-eval-at last`, only the `frac == 2` event has them; (b) with `--gen-eval 0`, `eval` events lack all three keys; (c) test the sampling function alone: sampling the same batch of events twice gives the same result; (d) a guard test: read `train_causal_share.py`'s source and use `ast` to find `_attn_ctx`'s `Call` nodes, asserting the only enclosing function is `_forward_packed` (the `def _attn_ctx` line itself doesn't count as a call), with a failure message citing spec 16.10 #29; (e) pass a counting `beat` to `eval_ce`, and with a hand-built event list of >= 25 physical blocks, assert it's called at least once.

## Background

In the final verification, the fixed probe (ticket 06) still reads a fullest block of 54.38 GB against a full-run `step` peak of 58.47 GB, 4.1 GB short. 8-28-assistant-2's read, after reproducing the block shapes in design-attention section 8.6: the peak-window block is simultaneously the block with the most loss positions (B=3, L_pad 5,344, 4,736 loss positions); each loss position costs about 1.8 MB extra at the output layer (four 151,936-dim vectors), and a probe that picks blocks only by token count misses this term. Correcting the probe by 2.7 MB x tokens + 1.8 MB x loss positions gives 54.38 + 1.83 x 2.752 - 2.7 x 0.352 = 58.5 GB, 0.1 GB from the measured 58.47. gyb wants the fallback turned into a switch.

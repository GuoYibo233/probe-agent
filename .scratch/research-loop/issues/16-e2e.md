## 九场景（每个一个 test 函数，序号与 spec §9 一致）

1. **正轨闭环**：写正轨单（spec_ref=IT-001、issue_ref、decision_refs=[D001]）
   → launch.py（ok）→ output_check ok → record.py 落两行 → 写批次报告
   plans/<batch>.md（frontmatter 齐、inspection_report 先空）→ 造干净核查
   报告 reports/inspection-<batch>.md（verdict: clean，体裁过 evidence_lint）
   → 报告头回填 inspection_report → `story add`（evidence 用该 run）→
   `trace_check --closeout <batch>` exit 0。
2. **快车道**：quick=true 单（三 refs 空）→ launch → record → runs 行
   quick=true；`story add` 引用它 → 拒；`trace_check`（无 closeout）不因缺
   spec_ref/issue_ref 报断链 → exit 0。
3. **转正重跑**：以场景 2 的 quick 单为模板造正轨单（promoted_from=
   quick run_id，seed/dataset_version/argv(改 --out 之外逐字)/env_name/
   filter 沿用；--out 指新 artifact_dir——argv 沿用面在 trace_check 按五
   字段整组比对，本场景 argv 完全逐字沿用、产物目录用 artifact_dir 字段
   区分即可，argv 里 --out 也保持逐字）→ launch → record → 新 run
   `story add` 放行；两条 runs 行（同 metric_name=acc）value **逐字相同**
   （fake_metrics 由 result.jsonl 字节决定，同 seed 同 mode 字节同）。
4. **empty 模式**：--mode empty 单 → launch exit 0 → output_check 判
   empty-output → `record.py --status empty-output` → runs 行
   status=empty-output 且 metric_name/value/n 全 null。
5. **bad-metrics**：--mode bad-metrics → launch ok → record exit 2、runs
   无新行 → 按 R8 开 blocked：`ledger.py blocked open --layer run
   --to-layer deploy --kind failure --ref <run_id> --question ...
   --evidence <attempt log 路径> "tried: reran record once"` → blocked 账
   新增一条 kind=failure 且 evidence 含日志路径（断言）。
6. **fail 后重试 ok**：--mode fail 单 → launch exit 非 0（attempt 1）→
   同 run_id 重写发射单（argv 的 --mode 改 ok；重写同路径幂等）→ launch
   （attempt 2 ok）→ record → runs 该 run_id 恰一行组 status=ok；RUNMETA
   attempts 两条俱在、第一条 argv 仍含 "fail"、log 路径文件未被覆盖
   （内容仍是失败输出）。
7. **批准失效**：approve 过的 spec 正文改一字 → 写新正轨单被
   `approval_stale` 拒。
8. **三类半状态收敛**：裸写造出孤儿 decision / 撤销中断 / affects 缺失
   三 fixture（同 T14 定义）→ 分别重跑原命令（blocked answer /
   blocked withdraw / launch-order 重写）→ 每类收敛到完整新状态：
   实体数量与引用关系与"一次成功执行"的结果逐字段一致。
9. **新会话接手**：以上任一沙盒里只跑 `ledger.py status --layer deploy` →
   输出 JSON 能解析、四断点字段与盘上事实一致（拿场景 4 的沙盒断言
   unrecorded_runs 或 batches_pending_report 非空即可）——不靠任何会话记忆。

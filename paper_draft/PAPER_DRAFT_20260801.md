## 题目（工作版）

**在 agent 写完思考之前：读思考文本的探针、工具调用的投机执行，与相似重复任务上的速度-准确率联合评测**

## 摘要（草稿）

会用工具的 agent 在每次调用工具之前，先要写一段思考文本。这段文本写完才发调用，于是工具的等待时间全部暴露在响应时间里，思考本身也要花 token。我们问三个问题。第一，如果能提前知道调用内容，提前拿到结果值多少钱——什么时候注入、注入什么，收益差多远？第二，能不能训练一个小的探针，只读 agent 写到一半的思考，就提前预测出它接下来要调的工具和参数，并且准到敢替它先把调用发出去？第三，agent 在相似的任务上反复做，速度和准确率的联合变化该怎么量？围绕这三个问题，我们给出四个部分：C1 用"事后已知正确结果"的注入实验量出收益随注入时机的完整曲线，发现贴近调用点注入反而负收益（下称死区）；C2 训练探针，在三个环境上按统一回放协议判定，并把探针接到真实服务上做注入实测；C3 建一个任务相似度可控、把省下的 token 和做对的题放在同一张图上的评测基准；C4（未开工）把自己的探针当被试放上 C3 的基准，产旗舰图。

## 1 引言

一个 agent 做任务的循环是：读环境返回，写一段思考，发一个工具调用，等结果，再思考。两笔开销都在思考侧：思考文本本身按 token 计费，工具的等待时间又完全串行在思考之后。但思考写到一半的时候，接下来要调什么往往已经定了——问题是没人去读这段半成品。

我们的主张分三层，每层都有实测支撑，也各有边界。

第一层，**提前拿到工具结果确实值钱，而且什么时候拿有讲究**。把事后已知的正确结果在思考的不同位置注入，开场注入能省 81–91% 的思考 token 而答对率不掉（账外，出自 oracle 注入线的结论报告；合成任务，五个模型乘六十题）；但贴近调用点（提前 25–50 个 token）注入是负收益。这个死区后来在真实多跳问答上带着误差棒复现（记录 `20260730_0413_hotpot_t11_var`），又在真实 agent 环境加真实探针驱动下第三次复现（记录 `20260801_0113_inject_aw_gptoss_r10`）。死区的存在意味着"什么时候动手"必须学，这是全篇的立论。

第二层，**从思考文本提前看出工具调用是可行的，但可行性由环境性质决定**。我们在三个性质拉开的环境上训探针、用同一个回放协议判定。工具少而格式固定的环境（bfcl）稳定达标；工具多而参数复杂的环境（appworld）要靠换探针底座或砍掉输入里的历史段才达标；动作空间开放的环境（tales）所有已测做法全部不达标。

第三层，**省 token 这条轴必须实测，而实测里埋着一个测量学问题**。我们把探针接到真实服务上做注入实测，发现"整段续写的 token 总量"这个求和口径的省 token 数，被服务端的生成不稳定性淹没：同一个事件两次跑可以差出 8161 个 token，对照实验给出的噪声地板比六个触发门槛点的全部差异还大（记录 `20260801_0413_aw_gptoss_th0925` 等六条）。所以主报口径改用逐事件中位数与"省为正的比例"，求和口径在论文里只能报为不可解读。

## 2 与已有工作的关系

以下每篇都亲自核对过摘要或全文，定位一句话说清（详细对标记录在项目的论文笔记里）。

- **SPORK**：免训练的自投机——让主模型自己分叉出一条解码线去猜完整调用。工具名准确率 74.6–99.6%，但参数在思考起点的正确率只有 7.6%。我们的差别：探针是训练出来的小模型，零额外解码开销，且逐句连续更新。
- **PASTE**：从历史日志离线挖模式来预测调用并投机执行，任务时间降 43.5%。它不在线学、冷启动是盲区；它最重要的教训是单侧加速会把瓶颈转移到服务侧，所以我们的计时设计里强制带服务侧对照。
- **When2Tool**：证明"是否需要工具"这个信号在隐藏状态里线性可解码（AUROC 0.89–0.96）。它只做二分类、只在生成前读一次；我们读的是思考文本、逐句连续读，并且从"判别"走到"投机执行闭环 + 参数 + 时机"。
- **Speculate with Memory**：外部小模型当投机器，已经画了随经验增长的学习曲线。它不读主模型内部、纵轴是估算节省不是实测。
- **PPRAG**：读隐藏状态做解码中途预取注入，延迟降 43.5%，但只限检索域。
- C3 侧的竞品（StreamBench、LifelongAgentBench、Evo-Memory、EvoMemBench、MemoryAgentBench）全部只报准确率类指标随经验的变化；把"省多少 token/时间"和"做对多少"作为联合学习曲线、且任务相似度参数化可控的基准，这个格子是空的。

## 3 任务环境

探针线（C2）用三个环境加一个新环境，C1 与 C3 各有自己的任务源。每个环境说三件事：任务长什么样、规模多大、它在实验里扮演什么角色。

**bfcl（多轮工具调用评测集）**。取其中多轮对话类的 200 道题：用户来回说几轮话，agent 在中间调函数。工具种类少、参数格式固定。它是探针的"顺风场"：工具类数约 101–106（随数据版本），先验基线（永远猜训练集里最高频的那个工具能猜对的比例）只有 0.038–0.049，探针只要学到东西就能拉开差距。

**AppWorld（模拟手机应用世界）**。agent 在模拟的手机生态里完成订票、发消息类任务，工具多、参数复杂。早期实验用它的 dev 段 57 题自己切分；2026-07-31 起换成官方题单分区：训练 90 题、验证 57 题、正常难度测试 168 题，合计 315 个任务实例，三个 agent 模型逐题对齐（记录 `20260731_0607_w0_aw_official`，594 条轨迹采齐）。按模型分成三个数据集后，工具类数 85–151，先验基线 q35 侧 0.174、q36 侧 0.159、gpt-oss 侧 0.404——gpt-oss 侧的先验基线高出一倍多，横比绝对精度会高估它，论文里凡引 gpt-oss 侧成绩必须连先验基线一起报。

**TALES（文字冒险游戏，烹饪主题）**。agent 用自然语言指令玩游戏。它能说的话几乎没有边界——我们把这个性质叫开放动作空间：没有一份固定的动作清单可选。进训练数据的那批轨迹是 20 个种子、40 步上限的设定（注意：项目内另有一批更大参数的探索批没有进数据，两批别混）。它是探针的"逆风场"，也是负结果的来源。

**ALFWorld（文字家务模拟器）**。模型读一段房间描述，逐条发动作指令。两个用途：C3 的存解法实验场地（任务按相似度分档），以及 2026-07-31 起探针线的第四个环境——官方分区训练 200 / 验证 140 / 测试 134 题，q36 与 gpt-oss 各采 474 条轨迹全清（记录 `c2_alfworld`）。它的性质与 AppWorld 相反：动作切成工具后词表只有 12 类，"去某处"这一个动作占 50.5%，先验基线高达 0.505——探针的工具头必须显著超过 0.505 才算学到东西。

**HotpotQA 与 2WikiMultihopQA（多跳问答）**。C1 的场地。两跳题分两类报：两跳互相独立的（比较型）与第二跳依赖第一跳答案的（桥接型）。2Wiki 同时是 C3 里 L3/L4 任务对的原料。

**真实负载记录（TraceLab）**。一批脱敏的真实编程 agent 使用记录，357000 次交互、4265 个会话。用来回答"相似任务反复出现"这个前提在真实世界成不成立。它只暴露工具调用构成、不暴露任务内容，这条边界在论文里声明。

## 4 模型

模型分三组，角色不同，全文不混用。

**产生轨迹的 agent 模型（三个，全部本地起服务，零付费接口）**：qwen3.5-27b（简称 q35）、qwen3.6-27b（简称 q36，混合架构）、gpt-oss-120b（开放权重，思考段取自专门的思考字段）。同族不合并：q35 和 q36 永远算两个模型。三个模型的思考风格差异本身是实验变量——同一道题，q35 侧样本的思考切 24 句，gpt-oss 侧切 38 句；gpt-oss 在 AppWorld 上思考文本长、切点密，事件数最少（3952）而样本数最多（166103）。

**探针底座（三个）**。探针是一个小的文本分类模型，读 agent 写到一半的思考，猜它接下来要调哪个工具。第一代底座是 ModernBERT-base，双向编码器，每探一次要把整段前缀重读一遍。后两个是因果探针底座：Qwen3-0.6B-Base 与 LFM2.5-350M-Base，只能从左往右读，读过的部分缓存下来不用重读，探测开销降到 ModernBERT 的 1/20–1/34（记录 `20260730_1716_bert_t8_causal`）。LFM2.5 是混合架构、许可非 Apache，论文如实标注。

**C1 与 C3 的被试模型**：C1 主用 Qwen3-8B（协议遵守率高），Qwen3.5-4B 因 48% 自发复读只报协议脆弱性不当被试；C3 的存解法实验用 Qwen3-8B（先行版用过 Qwen3.5-4B），六个记忆系统的对照统一换 Qwen2.5-7B-Instruct。

## 5 方法与评测协议

### 5.1 轨迹怎么变成训练数据

一条**轨迹**是 agent 做完一个任务的完整记录。轨迹里的一次工具调用连同它前面那段思考叫一个**事件**。把事件的思考按句子边界切开，每个前缀算一条**样本**：样本内容是任务描述加历史段加思考前缀，标签是这个事件真实调用的工具名，全自动、零人工。一个事件把所有句子边界都切出来（上限 64 个），训练损失里让每个事件等权——这样做是为了和部署时的分布对齐：真跑起来时每个句子边界都会问一次探针。

数据按**任务实例**切分（不是按轨迹）：同一道题在不同 agent 模型下的几条轨迹同进同出，防止同题的 q35 版本进训练、q36 版本进测试。切成四堆，比例 70/10/10/10：**训练堆**、**拟温度堆**（拟合温度，即把模型输出分数拉成可信概率的参数）、**扫门槛堆**（选触发门槛）、**测试堆**。随机种子全线固定为同一个数并写进报告，重跑必须逐样本一致。

### 5.2 回放协议与判定标准

评测走**回放**：把测试堆的轨迹按原顺序重读一遍，每个事件从思考第一句起逐句送进探针，置信度第一次超过**触发门槛**（θ）的那一刻记下预测，与真实调用对照。报四个数：**触发比例**（全部事件里探针敢出手的比例）、**触发时的预测准确率**、提前量（触发位置在整段思考里的靠前程度）、错误投机率。

门槛不是手工挑的：预设风险档（要求触发时的预测准确率 ≥95% 或 ≥90%），在扫门槛堆上找满足精度约束且触发比例最大的那一档门槛，然后**钉死**搬到测试堆——测试堆上的数字无论多难看都原样报告。一个环境要判**达标**，三条同时满足：触发时的预测准确率过线、触发比例不趴地、显著高过先验基线。

### 5.3 四格训练法

同一份数据，探针按"底座 × 头"组成四格，名字全文固定：**mtool**（ModernBERT 底座 + 工具名分类头）、**mext**（ModernBERT 底座 + 抽取头，指出参数值在文本里的起止位置）、**ctool**（因果底座 + 工具名分类头）、**cgen**（因果底座 + 生成头，直接把完整调用文本续写出来）。参数格的评测挂在同底座工具格选出的触发点上：触发那一刻才去抽参数或生成调用，量的是"真要投机的那一刻"的成绩。因果格开训前强制过对齐检查：整段一次前向与分块增量前向的输出必须一致到数值噪声以内，因为混合架构在增量喂入时出过静默算错的先例。

参数按**参数三档**分开报：**无参**（调用不带参数）、**选择**（参数值是上文里能找到的原字符串）、**自由**（值得现编）。判定抽取头时"答对抽不到也算对"，因为触发那一刻值常常还没写出来——先行试点量出提前 25 个 token 时参数字面串只有 33.8% 已经出现。

### 5.4 注入实测协议

离线回放算出的省 token 是估算。实测协议分三段：先按给定门槛在测试堆轨迹上重排出全部触发点（不碰 GPU）；然后对每个触发点做两条臂的真实续写——**不注入臂**（从触发点原样续写到底）与**注入臂**（在触发点把预测调用的结果以文本形式塞进上下文再续写）；最后对账，量 token 差和续写出的调用与真实调用的一致率。

猜错的事件怎么处理分三档口径：**跳过档**（猜错就不注入，只记账——偏乐观，真部署时探针不知道自己猜错）、**上帝档**（一律注入正确结果，给注入机制本身封顶）、**执行档**（猜错也在环境里真执行预测出的调用、把真实返回连同报错注进去——猜错的代价进账）。一个 2026-08-01 查明的口径更正必须写进论文：执行档一个事件只续写一步，不跑完整题，所以它量到的仍是**单步调用一致率**，不是任务级正确率；真正的任务级那条轴要另建"采集循环里挂探针、触发就注入、走完整题再评测"的在线实验，属于新增工作量。把执行档写成任务级正确率就是虚报。

主报形式已定为**门槛扫描曲线**：横轴触发门槛（六个格点，0.50 / 0.70 / 0.80 / 0.875 / 0.925 / 0.95），纵轴两条——省 token 与调用一致率。风险档选出的那两个门槛改述为曲线上标注的推荐工作点。

### 5.5 C3 基准协议

任务按与之前做过的题的相似度分**相似度三档**：完全一样的题、几乎一样的题、同类但换了东西的题（另有两个诊断档在造：构件都见过但组合没见过、表面像但照抄必错）。一次实验单元是"同一条臂连做十轮"：**存解法**臂每轮做完把做成的题目原文和成功动作串存起来，下一轮取最近五轮里做成的整段放进提示最前面；**不存解法**臂每轮从零开始；**全历史臂**把之前每轮的完整记录全放进提示，超预算从最旧的丢。判定货币是总 token：发进去的和写出来的加在一起——只数写出侧会让存解法永远不输，因为它多读的那部分没被算进去。上限基线是逐字回放：凡与前面某轮完全同题就记零花费，量出"靠照搬最多省多少"。配套指标（速度提升、达标累计成本、负迁移指数）已形式化，聚合必须含失败任务。

## 6 已完成实验与结果

### 6.1 C1：提前注入的收益与死区

上帝视角注入（结果事后已知、注入位置自由选）在合成任务上量出三件事（账外，出自 oracle 注入线结论报告）：授权措辞下开场注入省 81–91% 思考 token、答对率不低于 0.98；提前 25–50 token 的贴近注入负收益（死区）；错误结果注入后答对率崩到 0.02–0.14——"接受但不轻信"的训练必要性由此量化。真实多跳问答上（HotpotQA，Qwen3-8B，温度 0.6、三个种子、1338 条记录）：比较型早注掉 0.18 的宽松判对率，桥接型死区处 token 净亏 153 个，三条主线结论跨种子稳（记录 `20260730_0413_hotpot_t11_var`）；"开场注齐全部证据"是全场最优动作，桥接型省 457 token 且答对率 +17 个百分点（账外，出自 C1 结论报告第二波）。

### 6.2 C2 离线探针：三代训练与三环境判定

第一代（v2）因浮点格式设错作废：权重直接存 bf16，学习率算出的更新量低于 bf16 分辨率，模型近乎冻结（记录 `20260729_2106_bert_replay_bfcl_v2`：按思考深度分桶的准确率全程平在 0.26，无可用门槛）。修复版（v2fix，权重 fp32、计算降 bf16）在 bfcl 上翻案：门槛 0.925 时触发时的预测准确率 0.966、触发比例 0.620，先验基线 0.038 被碾过（记录 `20260729_2235_bert_replay_bfcl_v2fix`）。数据翻倍代（v3）终审三环境：bfcl 达标（0.9925 / 0.5929，记录 `20260730_0204_bert_replay_bfclv3`，且换切分重跑与 v2fix 置信区间互覆、切分方差约 ±3 个百分点）；appworld 不达标（精度钉在 0.933，风险 0.05 档无可用门槛，记录 `20260730_0814_bert_replay_appworld_v3`）；tales 不达标（精度天花板 0.84–0.85，差 10 个百分点，归因开放动作空间，记录 `20260730_1645_bert_replay_tales_v3`）。

### 6.3 信号来源分解

砍掉思考段重训，bfcl 触发比例从 0.5929 跌到 0.0752；砍掉历史段只到 0.4823——主要增量信号在思考文本里（记录 `20260730_1713_bert_t5_ablation`；两个触发比例账外，出自各格回放报告；注意砍思考档的回放退化为每事件读一次，触发比例口径与完整输入不同，成表时须标注）。意外收获：appworld 砍历史后 0.954 / 0.22，第一次在 95% 标准下达标——历史段在这个环境里是有害噪声。

### 6.4 跨模型矩阵与混训

把数据按 agent 模型切成两侧，每侧训探针、按主场 / 冷迁移（什么都不重调）/ 只换校准（权重不动，只换拟温度堆和扫门槛堆）三种考法考（记录 `20260730_1713_bert_t6_xqwen`、`20260730_1716_bert_t6_xgptoss`）。部署结论按环境分开写：bfcl 换 agent 模型只需重做校准（主场 0.9748、冷迁移 0.897、只换校准救回 0.971，代价是触发比例减半）；appworld 只换校准救不满（0.8824，账外，出自该格回放报告）；tales 全弱。混训（两侧轨迹合训）把 bfcl 的天花板抬在触发比例上：qwen 侧 0.9645 / 0.7478（记录 `20260730_1835_bert_t6_bfcl_mixed`），对照纯 qwen 训练同口径的 0.9913 / 0.5088（账外，出自该格回放报告）——精度略降、触发比例大涨。

### 6.5 因果探针裁决

换因果底座后 appworld 的门被打开：Qwen3-0.6B 底座 0.9621 / 0.3338，而 ModernBERT 读完整输入在同环境同档找不到可用门槛；三环境触发比例全面升 2.5–4.3 倍，探测开销降到 1/20–1/34；把 tales 窗口从 4096 放宽到 8192 只有噪声级收益，窗口不是瓶颈（记录 `20260730_1716_bert_t8_causal`；LFM2.5-350M 底座的六个数账外，出自各环境回放报告）。这一步定了主线换轨：因果头当主线，ModernBERT 分类头退为对照（TIMELINE 2026-07-31 条目）。

### 6.6 抽取头

bfcl 上触发时刻的完整调用正确率 0.918（对照 SPORK 的参数起步 7.6%），选择档 0.893；真瓶颈不在抽取而在"触发那一刻值还没写出来"：自由档触发时值已出现的比例只有 0.235（记录 `20260730_1713_bert_t7_extractor`；该分档数账外，出自抽取评测报告，总账里只有整体值 0.7612）。论文该报的数是触发时值已出现的比例——它是投机覆盖面的上限。

### 6.7 新场地首战：AppWorld 官方分区十二格

官方题单分区上，三个 agent 模型 × 四格全训全评（记录 `c1_*` 十二条，2026-07-31）。三条结论。其一，因果头全面胜出：gpt-oss 侧 ctool 双档有解（风险 0.10 档触发比例 0.4963 / 准确率 0.9057），同源 mtool 一档无解一档未兑现；触发比例上 ctool 是 mtool 的 1.7–4.0 倍。其二，难度迁移风险兑现一例：gpt-oss 侧 mtool 在扫门槛堆上选出的门槛搬到测试堆后准确率只有 0.8642，低于 0.90 的契约线——扫门槛堆上选点不保证测试堆兑现。其三，宽松与严格判定的差距只出现在抽取路线：三个 cgen 的参数全对率宽松严格完全相等（0.9041 / 0.8582 / 0.8262），而 mext 差距悬殊（gpt-oss 侧 0.7887 对 0.4377）。q35 侧 mtool 两档皆无解，连带其 mext 无法评测——这本身是"探针可行性由数据成色决定"的一格证据。

### 6.9 注入实测：单点全量与门槛扫描

单点全量（AppWorld，gpt-oss 侧，门槛 0.925，跳过档，1061 个触发事件里 689 个注入）：注入被模型采纳——注入后模型顺着结果推进的比例 0.62，不注入对照只有 0.10；但省 token 强依赖时机：思考前 20% 注入平均省 377.7 token，后 40% 注入亏 636–697 token，而探针置信度触发有 21.8% 恰落在最差区间，总体被拉平到中位数 −27（记录 `20260801_0113_inject_aw_gptoss_r10`）。死区第三次复现，这次是真实环境加真实探针。

## 8 局限与已知缺口

写进论文前必须处理或声明的账，按重量排。

1. **闭环真实计时一次没跑**。全部省 token 数字来自离线回放或单步续写实测；审稿人会要真实墙钟。管线代码已备，端到端演示未跑。
2. **求和口径省 token 不可解读**已如实入账，主报改逐事件口径；服务侧噪声地板（0.1528）与撞 8192 上限的失控生成要在论文里当测量学发现写，不当瑕疵藏。
3. **任务级正确率轴不存在**。现有正确率全是单步调用一致率；执行档也只能修"猜错代价记零"的乐观偏差，给不出任务成败。
4. **tales 全线不达标**是结论不是遗留：开放动作空间下探针路线的边界，论文当负面案例写。
5. **BFCL 的两个悬案**：q36 反低于 q35（0.59 对 0.70）疑与聊天模板套用有关未查清；参数重抽多出 217 个事件未查清。引用相关数字前先确认不受影响。
6. **两套相似度档编号取值正好颠倒**（原始文件用代码那套，正式文档用正典那套），引用带 L 的数字必须先对表。
7. **跨批次 token 数不可直接比**：换推理服务能让同一条臂差出几十个百分点，凡跨批比较必须确认同一套服务；耗时只认同卡配对。
8. **训练发射时工作树全脏**：多数记录的代码版本追不回，可复现性靠数据种子与验收线兜底，论文的复现声明要如实写。
9. **六被试里的失真**：两个重建系统失真需声明、一个机制缺失建议不报，正式跑分前先修答案抽取与判分。
